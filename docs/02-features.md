# TV Shifts — Функционал

## Роли

| Роль | Описание |
|------|----------|
| **Сотрудник** | Видит свой календарь, смены, лог изменений, берёт задачи из бэклога |
| **Администратор** | Полный контроль: подтверждение смен, редактирование, все логи, управление проектами и пользователями |
| **Продюсер** | Чтение: производственный календарь, загруженность команды; может запустить синхронизацию вручную |

---

## Производственный календарь

- Навигация по неделям (назад / вперёд)
- Каждый день отображает проекты и занятых специалистов
- Правая панель: список **неподтверждённых проектов** (без конкретной даты — только месяц или вообще без даты)
- Клик на проект → детальная карточка

### Статусы проекта

| Статус | Источник | Визуал |
|--------|----------|--------|
| **Предварительно** | Таблица проектов (подсвеченные ячейки) | Жёлтый |
| **К реализации** | Таблица проектов (все поля утверждены) | Зелёный |
| **Завершён** | Таблица проектов / вручную | Серый |
| **Ручной** | Создан внутри приложения администратором | Синий |

### Конфликты

- Один сотрудник на двух проектах в один день → строка/карточка подсвечивается красным
- Из карточки конфликта можно переназначить сотрудника на один из проектов

---

## Детальная карточка проекта

- Название, клиент, формат, дата, время
- Ответственные: исполнительный продюсер, линейный продюсер, аккаунт-менеджер
- Список специалистов с датами смен и типами смен
- Штатные сотрудники выделены отдельно от фрилансеров
- Статус синхронизации (из таблицы / ручной / конфликт)
- Ссылка на матрицу в Google Sheets

---

## Типы смен

Определяются автоматически из позиции в матрице (относительно даты проекта):

| Тип | Когда |
|-----|-------|
| **Застройка** | За 1–3 дня до даты проекта |
| **Эфир** | В день проекта |
| **Демонтаж** | На 1–3 дня после даты проекта |

Каждый выход = 1 смена = 1 балл.

---

## Учёт смен

### Формула минимума на месяц

```
min_shifts = ceil(рабочих_дней_в_месяце × 16 / 22)
```

Единая для всей команды, пересчитывается каждый месяц.

### Логика

| Ситуация | Действие |
|----------|----------|
| Смен > минимума | Автоматически фиксируется как **переработка** |
| Смен < минимума | Администратор вручную добавляет **отпуск** |

### Подтверждение смен

- В идеале сотрудник ничего не заполняет — смены берутся автоматически из матриц
- Администратор **подтверждает** или редактирует смены
- Сотрудник не может редактировать или backdatе; администратор может всё

## Синхронизация с Google Sheets

- **Авто**: каждые 30 минут
- **Вручную**: кнопка «Обновить данные» (администратор, продюсер)
- **Источники**: только чтение — запись в таблицы не производится

### Порядок синхронизации

1. Читаем таблицу проектов → обновляем список проектов и статусы
2. Читаем реестр матриц → получаем список матриц и ссылки
3. Для каждой матрицы: читаем лист «₽ СМЕНЫ» → извлекаем специалистов и даты
4. Маппим ФИО из матрицы на аккаунты системы (точное совпадение)
5. Обновляем производственный календарь

### Конфликт данных (merge UI)

Когда синхронизированные данные расходятся с ручными записями:
- Показывается diff-панель: наш вариант слева, входящий справа
- Кнопки: **«Принять наше»** / **«Принять их»**
- При следующей синхронизации снова проверяем расхождения

## Уведомления (колокольчик)

Правый верхний угол. Группы уведомлений:

| Тип | Описание |
|-----|----------|
| Нет матрицы | Проект есть в таблице проектов, но матрица не найдена |
| Неизвестный сотрудник | ФИО из матрицы не найдено среди аккаунтов системы |
| Конфликт данных | После синхронизации обнаружены расхождения с ручными записями |
| Изменение расписания | У сотрудника изменились проект, дата или тип смены |

---

## Лог изменений

- **В аккаунте сотрудника**: его изменения расписания (новый проект, перенос, смена типа смены)
- **В admin-панели**: все изменения по всем сущностям с указанием автора и источника (синхронизация / вручную)

---

## Admin-панель

- Список сотрудников: создание, редактирование, маппинг ФИО ↔ аккаунт
- Ручное создание проекта (статус «Ручной»)
- Подтверждение смен
- Управление бэклогом задач
- Настройки синхронизации
- Полный лог всех изменений с фильтрами

---

## Бэклог задач

- Общий список задач (не привязан к конкретному проекту)
- Сотрудник открывает бэклог → берёт задачу → статус меняется на «В работе»
- Статусы: **Открыта / В работе / Выполнена**
- Администратор видит: кто, что и когда взял и выполнил
- **Будущее**: администратор начисляет бонусные баллы за выполненные задачи

---

## Дашборды (аналитика)

- Сколько смен отработал каждый сотрудник за месяц / квартал
- Переработки и отпуска по сотрудникам
- Кто на каких проектах участвовал
- Загруженность команды по периодам
- Выполненные задачи по сотрудникам
