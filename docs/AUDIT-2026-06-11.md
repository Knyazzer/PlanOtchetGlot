### Code review — API

14. 🟡 **Гонка в `nextTabNumber()`** (`users.ts:35`): два параллельных POST /staff получат одинаковый `max+1`; `tabNumber` в схеме БЕЗ `@unique` → дубль запишется молча. Практическая вероятность низкая (один админ), но констрейнта нет. Рекомендация: `@@unique` на (`tabNumber`) или (`userType`,`tabNumber`).
15. 🟡 **`deactivate` глотает ошибку бана GoTrue** (`users.ts:226-230`): `.catch(() => {})` — если Supabase недоступен, ответ всё равно «уволен», но auth-аккаунт НЕ забанен → пользователь сохраняет вход в inventory (сессии/refresh живут). Рекомендация: проверять `res.ok`, возвращать предупреждение в ответе.
16. 🟡 **PATCH /users/:id принимает `isActive`** — обходной путь мимо deactivate/reactivate: не банит auth, не синкает `public.users`, не снимает табельный. Рудимент до появления lifecycle-эндпоинтов. Убрать из схемы PATCH.
17. 🟡 **`generateEmail()` коллизия тёзок** (staff): два «Иванов Иван» → одинаковый сгенерированный email → 409, создать второго нельзя (поле email в POST /staff не передаётся). У фрилансеров решено суффиксом табельного.
18. 🟡 **Дубль `genTempPassword`/`PW_CHARS`** в `routes/auth.ts:8-14` и `routes/users.ts:9-15` — вынести в общий хелпер.
19. 🟡 **`/users/bulk-register`** — legacy-307-редирект на bulk-import-staff. Проверить вызовы с фронта; вероятно удалить (упоминается только в DEPLOY-RUNBOOK.md).
20. ⚪ `fetch` к Supabase admin API без таймаута (onboard/bulk-onboard/reset-password/deactivate) — зависший Kong подвесит запрос.

### Code review — API (продолжение)

22. 🟠 **`structure.ts` — все роуты без admin-гарда и без Zod.** Каждый эндпоинт (`POST/PATCH/DELETE /structure/departments|divisions|memberships`, `POST /structure/migrate-from-sheets`) защищён только `authenticate`. Любой аутентифицированный сотрудник через curl может удалить департамент — каскадом снесутся divisions и memberships (`onDelete: Cascade`). Сегодня риск смягчён visibility gate (не-админы не видят AppShell), но API открыт. **Закрыть до открытия приложения сотрудникам.**
23. 🟠 **`.parse` вместо `.safeParse`** в `projects.ts:97,104,138,201` и `clients.ts:16,25` — невалидное тело (`POST /projects {}`) бросает ZodError → 500 вместо 400+details. Нарушение собственного контракта (RULES §4).
24. 🟠 **`seedSheetConfigsFromEnv()` затирает настройки при каждом старте** (`databaseService.ts:75-90`): upsert безусловно перезаписывает `sheetUrl`+`apiKey` значениями из env/дефолтов. Сценарий: админ сменил URL таблицы через UI (PATCH /database/config) → деплой/рестарт → настройка молча откатилась.
25. 🟠 **Захардкоженный Google API-ключ** в `databaseService.ts:65` (`DEFAULT_API_KEY = 'AIzaSy…'`) + URL корпоративных таблиц. Ключ в git-истории. Внести в план ротации (вместе с JWT_SECRET), убрать дефолт из кода — только env.
26. 🟠 **PATCH /events/:id не синхронизирует задачи-спутники при смене участников** (`events.ts:153-192`): participants заменяются, но авто-задачи создаются только в POST. Добавленный участник не получает задачу; у удалённого задача остаётся и продолжает показываться в его календаре/канбане. Синхронизируется только время/название.
27. 🟡 **`GET /tasks?scope=team` отдаёт все задачи компании любому пользователю** (`tasks.ts:54`) — параметр не ограничен ролью. Вероятно осознанная прозрачность, но подтвердить намерение.
28. 🟡 **DELETE /work-items/:id доступен любому аутентифицированному**, тогда как DELETE /projects/:id — только админу. Несогласованная модель прав. Также PATCH/DELETE `expenses/:expId` и `stages/:stageId` не проверяют принадлежность родителю из URL.
29. 🟡 **Advisory lock через `$executeRawUnsafe` с интерполяцией** (`chats.ts:150,187,207`) — сейчас безопасно (значения проходят проверку существования), но паттерн инъекционно-хрупкий: убрать предварительную проверку — откроется дыра. Перевести на параметризованный `$queryRaw`.
30. 🟡 **`GET /chats/unread` — N+1**: по одному `message.count` на каждый чат (Promise.all) каждые 15 секунд с каждого клиента. Заменить одним groupBy-запросом.
31. 🟡 **Polling отсутствует на ProjectsPage и CalendarPage** — RULES §2 объявляет его обязательным. Есть только на TasksPage (30s), ChatsPage (10s), бейджи AppShell (15s).
32. ⚪ JWT_SECRET fallback `'dev-secret-change-in-production'` в `server.ts:66` — в production лучше fail-fast при отсутствии env.
33. ⚪ Бан GoTrue не отзывает уже выданные access-токены — окно «уволенный ещё внутри inventory» = TTL токена (≤1ч). Nexus блокирует сразу (isActive в плагине).
34. ⚪ POST/DELETE /events: событие и задачи-спутники создаются/удаляются вне транзакции.
