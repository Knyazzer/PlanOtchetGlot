# Спека: единые шапки страниц (ui-kit AppShell, Задача 5)

> Статус: утверждён Владом 2026-08-01. Часть адаптации Nexus на единый ui-kit AppShell.
> Предыдущие этапы (parity, лого «Нексус», iconSrc-логотипы продуктов, слот уведомлений
> `headerActions`, порядок блоков меню) — завершены.

## Проблема

Китовая шапка AppShell (заголовок раздела + колокол уведомлений справа) — хорошая и её
оставляем как есть (размер/шрифт/подпись). Но каждая страница рендерит **свою** шапку с
контролами прямо под ней → визуальное дублирование. Нужно перенести контролы страниц в
китовую шапку и убрать дублирующие внутристраничные шапки.

## Механизм — HeaderPortal (кит НЕ трогаем)

Китовый `AppShell` уже принимает проп `toolbar` (правый слот шапки, группируется слева от
`headerActions`/колокола). Никаких новых пропов кита не нужно.

- Nexus `AppShell.tsx` создаёт DOM-цель и кладёт её в `toolbar`: `<div ref={setSlotEl} className="flex items-center gap-2" />`.
- Контекст `PageHeaderContext` отдаёт `slotEl` вниз по дереву.
- Компонент `HeaderPortal` (`components/HeaderPortal.tsx`): `const el = usePageHeaderSlot(); return el ? createPortal(children, el) : null`.
- Страница оборачивает свои контролы: `<HeaderPortal>{controls}</HeaderPortal>`. Состояние и
  хэндлеры остаются в странице — портал держит контролы в React-дереве страницы, рендерит их в
  DOM шапки. Нет подъёма стейта, нет сериализации.
- Цель хранится в `useState` (callback-ref), чтобы портал перерендерился, когда `<div>` шапки
  смонтирован. Страница без `HeaderPortal` → правый слот пуст.

Заголовок раздела в китовой шапке (напр. «Календарь», «Команда») даёт сам `AppShell`
(`activeTop.label`) — внутристраничные заголовки-дубли удаляются.

## Поповер «Календари» (замена левого сайдбара CalendarPage)

Кнопка «Календари ▾» в шапке → всплывающая панель-чеклист вкл/выкл отображения. Переиспользует
текущее состояние `visible` / `toggleCat` и списки категорий (`MY_CATS`, `HR_CATS`).

- Внутри: поиск по названию, свёрнутые группы (Мои / HR / …), цветная точка у каждой,
  «выбрать все / снять все». Группировка по типу/источнику, НЕ по департаментам.
- Масштабируется на большое число календарей (главная причина отказа от горизонтального ряда).
- Закрытие — **железное правило попапов**: закрывается только если И `mousedown`, И `mouseup`
  на оверлее (вне контента); Esc; кнопка ✕. НИКОГДА `onClick={close}` на оверлее.
- Левый `<aside>`-сайдбар категорий из CalendarPage удаляется; сетка занимает всю ширину.

## Слияние Аналитика + Свод

- Убрать `svod` из `USER_NAV` и из `type Page` (`AppShell.tsx`); убрать ветку `page==='svod'`.
- `AnalyticsPage` получает внутренние вкладки `[Аналитика | Свод]`; под «Свод» рендерит
  существующий `SvodPage` (как есть). Активная вкладка персистится (`localStorage`).
- Переключатель `[Аналитика | Свод]` уходит в китовую шапку через `HeaderPortal`.
- `SvodPage` не переписываем — только вкладываем; позже легко вынести в отдельный формат.

## Порядок реализации

1. **Инфраструктура**: `PageHeaderContext` + `HeaderPortal` + цель в `toolbar` (Nexus AppShell).
2. **Команда** — самая простая: h1/поиск/департамент → шапка.
3. **Задачи** — вкладки Задачи/Треки → шапка; вид/группировка остаются в контенте.
4. **Аналитика + Свод** — слияние в один пункт, внутренние вкладки, переключатель в шапку.
5. **Календарь** — контролы вида/навигации → шапка; сайдбар категорий → поповер «Календари».
