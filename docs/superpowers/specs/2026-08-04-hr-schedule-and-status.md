# A. График работы (HR) + единый статус — спека

> Пункт A мастер-плана (`plans/2026-08-04-nexus-master-plan.md`). Основано на решениях §3/§4 из `specs/2026-08-02-calendar-mechanics-decisions.md`. Ветка `knyazzer`, локально.

## Идея
HR при найме задаёт сотруднику **график работы** (недельный паттерн: тип дня по дням недели + рабочие часы). График даёт **тип дня по умолчанию** — подсказку в кабинете/сводке для незаполненных дней. Сотрудник отмечает факт (начало/конец), сам может поставить только больничный/отпуск (уже есть `apply-period`); остальное — HR/руководитель; командировка — из проекта (позже).

## Ключевой принцип
График — **прогнозная конфигурация**, НЕ факт. Дефолт из графика показывается как подсказка (бледно / предзаполнение формы), но **Свод/аналитика считают только реальные `DayEntry`** (незаполненный прошлый день остаётся пустым в отчёте). Неизменяемость исторических фактов не нарушается ([[data-immutability-audit-nexus]]).

## Модель данных (Prisma, nexus)
```
model WorkSchedule {
  id        String   @id @default(uuid())
  userId    String   @unique @map("user_id")   // один активный график на сотрудника (правится, не версионируется — это конфиг, не факт)
  user      User     @relation("UserSchedule", fields:[userId], references:[id], onDelete: Cascade)
  mon..sun  String   // ключ DayFormatVersion (office|remote|shift_*|...) или 'dayoff'
  workStart String   @default("10:00")
  workEnd   String   @default("18:30")
  breakMin  Int      @default(0)
  updatedAt DateTime @updatedAt
}
```
Смена графика правит запись (история фактов — в `DayEntry`, их не трогаем). Для сменных команд (ТВ) паттерн может быть весь `dayoff` (нет фикс-графика) → подсказок нет, заполняют вручную.

## API `/work-schedule`
- `GET /me` — свой график (или `null` → клиент берёт дефолт 5/2 office).
- `GET /:userId` — HR/руководитель/директор/админ (орг-охват `getOrgScope`).
- `PUT /:userId` — задать/править график. Доступ: **admin или модуль `hr.orgstructure`/`hr.absences` (edit)**. Zod `.safeParse`.

## Дефолт типа дня (клиент, не авторитетно)
`expectedFormat(date, schedule)` = `schedule[weekday]`; часы = `workStart/End`. Применение:
- **DayFillCard**: пустой день → предзаполнить формат+часы из графика (пользователь может переопределить и сохранить — тогда это факт).
- **MonthStrip**: пустой день → показать ожидаемый тип **бледно** (не «не заполнен», а серым «ожид.: Офис»); заполненный — как есть.

## Шаги реализации
1. **Фундамент** (этот заход): модель + миграция + сид дефолт-графиков сэмпл-штату + API (GET /me, GET/:id, PUT/:id) + клиент (DayFillCard предзаполнение, MonthStrip ожидаемый тип).
2. **HR-конфиг UI**: раздел (Персонал/HR) — задать график сотруднику (паттерн недели + часы). 
3. **Единый статус/присутствие**: свести режим присутствия (офис/удалёнка/на проекте/не в рабочее) с `dayFormat` и Сводом; заменить бывшую заглушку «Мой статус». Правила авто-простановки 10:00–18:30.

## Открытые вопросы (дефолты приняты, помечено для Влада)
- Сменным (ТВ) график по умолчанию — весь `dayoff` (нет подсказок) vs office 5/2. **Дефолт: office 5/2** для демо; HR переопределит.
- Кто ещё правит график, кроме admin/HR — руководитель отдела? **Пока: admin + hr-модуль.**
