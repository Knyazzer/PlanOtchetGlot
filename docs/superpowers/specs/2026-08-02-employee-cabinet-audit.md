# Аудит «как есть» — кабинет рядового сотрудника (Nexus)

> Аудит поверхности не-админа 2026-08-02 (перед проектированием решения для сотрудника). Факты из кода; расхождения с `CLAUDE.md` отмечены.

## 0. Критическая находка — visibility gate АКТИВЕН (не снят)
`CLAUDE.md` пишет «Visibility gate снят», но в коде (`App.tsx:125-130`) гейт работает:
`if (!user.isAdmin && !user.canAccessPlatform) return <PersonalCabinetPage user={user} />`.
Флаг `canAccessPlatform` — точечный бета-роллаут, выдаётся в Персонале («Доступ в платформу (бета)»). Итого **две разные поверхности**:

- **Дефолтный сотрудник (без флага, прод):** НЕ входит в AppShell. Видит только `PersonalCabinetPage` — карточка: имя/должность, «Перейти в Инвентаризацию» (если есть модуль `ext.inventory`, иначе «Доступ к приложениям пока не назначен»), сменить пароль, выйти. **Ни плана дня, ни задач, ни свода — ничего.**
- **Сотрудник с бета-флагом:** полный AppShell, приземление на «Главная», меню `USER_NAV`.

## 1. Меню сотрудника (с флагом)
Главная · Мой кабинет · Календарь · Задачи (+бейдж непрочитанных) · Аналитика (внутри вкладка «Свод») · Проекты · Команда. Плюс RBAC-допмодули секциями (напр. Инвентаризация), правая чат-панель, колокол, панель профиля. Настройки/Персонал/Списки — admin-only (personnel — не-админу при модуле `hr.orgstructure`).

## 2. Состояние вкладок (реально / заглушка)
- **Главная (`HomePage`)** — 🔴 **ПОЛНАЯ ЗАГЛУШКА**: 4 карточки с плашкой «В разработке» (Новости компании, Кто работает сегодня, Глобальные задачи, Статусы и дедлайны). Данных нет. Это страница приземления.
- **Мой кабинет (`DashboardPage`)** — 🟢 работает: `DayFillCard` (план дня) + «Задачи на сегодня» + «Дедлайны» (1/3/7д) + «События сегодня»; создать задачу/событие, отметить done.
- **Календарь** — 🟢 работает (месяц/неделя/день, события + HR/Знаменки-записи, поповер «Календари»). HR-записи пишет только модуль `hr.absences`; сотруднику read-only.
- **Задачи** — 🟢 работает (Доска/Таблица/Гант, группировки, «Мои/Отправленные», TaskModal, polling). Смена исполнителя — только автор/admin; смена статуса — только исполнитель.
- **Аналитика + Свод** — 🟢 работает. Аналитика: KPI+чарт+вкладки+CSV, скоуп [Я|Команда|(Компания)] («Компания» — по модулю). Свод: сетка день×сотрудник отдела, клик → `DayModal` (свой день — правка).
- **Проекты** — 🟢 в основном; внутри `project-card/StructureTab` три блока «ЗАГЛУШКА · В РАЗРАБОТКЕ».
- **Команда** — 🟢 оргдерево, поиск, профиль-попап (⚠ попапы закрываются по document-mousedown, не по канон-правилу mousedown+mouseup-на-оверлее).
- **Настройки** — admin-only, фактически 2 вкладки (Роли, Бэкапы-заглушка). ⚠ `FormatsTab` («Форматы дня») написан, но **не подключён** — расходится с CLAUDE.md.

## 3. Потоки
**Создание задачи:** из «Мой кабинет» (+), «Задачи» (+Задача), Гант/Kanban → `TaskModal`. Поля: название, описание, исполнитель (дефолт — сам), тип, клиент, проект, план/факт мин, дедлайн (+3д), повтор, опц. трек/этап. Назначить себе — всегда; на другого — любой аутентиф. (роут не ограничивает); правка исполнителя после — автор/admin; статус — исполнитель. В день садится по `Task.startDate`. **Диапазонов нет** (вердикт В-1).

**Заполнение плана дня:** `day-entries` — сотрудник правит ТОЛЬКО свой день: `PUT /day-entries` (`dayFormat`, start/end/breakMin, снапшот divisionId). `dayFormat` — из **версионируемого справочника** (Q-DAY-5: прошлое по старым весам); формат несёт `isWork` + `score`. Часы = MAX(0, end−start−break). `apply-period` — формат на диапазон (отпуск/командировка/больничный), ≤370 дн, `keepFilled`. UI: **`DayFillCard`** (Мой кабинет) + **`DayModal`** (клик по ячейке Свода).

**Отчёт:** Свод (сетка отдела read-only, свои строки — правка; подвал часы/баллы/задачи; RBAC member/head/director/admin) + Аналитика (скоуп team по умолчанию; формулы: часы плана дня vs часы задач, loadPct, businessDays по календарю РФ).

**Статусы/присутствие — ДВА несвязанных:**
1. **Статус дня (`dayFormat`)** — тип рабочего дня (офис/удалёнка/отпуск/…) + балл + рабочесть; **пассивный** (заполняется вручную в DayFillCard/DayModal).
2. **Текстовый статус профиля (`user.status`)** — свободная строка в панели профиля, видна в попапе Команды. С `dayFormat` НЕ связан.
Живой «кто работает сейчас» — нет (карточка на Главной = заглушка).

## 4. Заглушки на поверхности сотрудника
- Вся **Главная** (4 карточки «В разработке») — единственная целиком-заглушечная вкладка внутри платформы.
- Дефолтный сотрудник без флага — вся платформа недоступна (гейт).
- Панель профиля → «Изменить пароль — скоро» (disabled) — при этом на PersonalCabinet смена пароля рабочая (расхождение).
- Настройки → Бэкапы (заглушка, admin-only); `FormatsTab` не подключён.
- Проекты → StructureTab (3 блока-заглушки).
- Чаты — «скоро» на отдельной функции.

## 5. Вывод для проектирования
Рабочие инструменты сотрудника (план дня, задачи, свод, аналитика, календарь, команда) **функционально готовы**, но:
- разбросаны по вкладкам и **не собраны в цельный «кабинет сотрудника»**;
- **Главная** — пустая (нет «домашнего экрана» дня);
- **два несвязанных статуса** (dayFormat vs profile.status), нет живого присутствия;
- **дефолтный сотрудник вообще не видит платформу** (гейт) — нужно решение по роллауту;
- новый календарь (день-вью, задачи-со-временем, статусы) должен **согласоваться** с несущей логикой план-отчёта (dayFormat, минуты, Свод), а не дублировать.
