# Дизайн: «Задачи на сегодня» как рабочий набор дня

> Дата: 2026-08-09. Статус: одобрено Владом (модель + кусок №1). Ветка `knyazzer`.
> Родитель: [CLAUDE.md](../../../CLAUDE.md) → раздел «Концептуальная модель». Смежное: [ECOSYSTEM-AGGREGATION.md](../../ECOSYSTEM-AGGREGATION.md) §9 (канон рабочей единицы), [DAY-STATUS-MODEL.md](../../DAY-STATUS-MODEL.md).

## Контекст и проблема

Блок «Задачи на сегодня» в Обзоре (`DashboardPage.tsx`) сейчас — «оконный» фильтр по дате (`startDate ≤ день && (нет дедлайна || дедлайн ≥ день)`), живущий отдельно от колонок канбана (`backlog → inprogress → done`). Влад хочет, чтобы этот блок стал **рабочим набором дня**, согласованным с доской: человек сам «накидывает» себе задачи на конкретный день, они же попадают в колонку «В работе», выполненные остаются зачёркнутыми, а порядок можно менять руками.

## Согласованная модель (весь жизненный цикл)

- **Бэклог = пул** всех задач. Назначенное (руководителем/коллегой) падает в Бэклог; человек **сам** вытягивает задачу в «В работе», когда берёт её.
- **Задача привязана к дню** (`startDate` = «день, на который задача поставлена в работу»). «Задачи на сегодня» = задачи с `startDate = выбранный день`, статус `inprogress` или `done`. Одновременно `inprogress`-задача видна в колонке «В работе» на канбане.
- **Выполненную не убираем** — остаётся зачёркнутой в списке своего дня. На следующий день выполненные не показываются.
- **Авто-переноса нет.** Переключил на другой день — там пусто, пока сам не накидаешь/не перетащишь. Незакрытая задача при этом жива в «В работе» на доске (просто не в списке другого дня).
- **Порядок внутри дня — ручной** (drag за grip «шесть точек»). У `Task` уже есть поле `manualOrder`.
- **Переходящая задача**: перетаскиванием (не выпадашкой) можно перекинуть задачу на другой день — `startDate` меняется, с текущего дня уходит.
- **История жизни задачи**: логируем, когда задача попала в исполнение, «прыжки» день→день, сколько висела/делалась, финальный день «готово». Анализ — позже.
- **Шаблоны**: именованные наборы преднастроенных задач (клиент/проект или самозадача + время); «шаблон на сегодня» добавляет задачи из шаблона в таблицу дня.

## №1 — Ядро: рабочий набор дня + связь с доской

### Поведение

1. **Список «на сегодня»** (`DashboardPage.tsx`, `dayTasks`): задачи, где `assignee = я` И `toDay(startDate) = selDate` И `status ∈ {inprogress, done}`. Уходит «оконный» фильтр. Календарные авто-задачи (`calendarEventId != null`) по-прежнему исключены (они — события).
2. **Inline-создание в Обзоре**: POST `/tasks` с `status='inprogress'`, `startDate=selDate`, `assigneeId=me` + `client/projectId/plannedMinutes/title`. → появляется в списке дня и в колонке «В работе».
3. **Чекбокс «готово»**: тоггл `done ↔ inprogress` (сейчас ошибочно `done ↔ backlog`). При `→done` проставляется `doneAt`; при `→inprogress` — `doneAt=null`.
4. **Выполненные остаются** зачёркнутыми в списке своего дня (даёт сам фильтр `status ∈ {inprogress, done}`).
5. **Без авто-переноса** — список строго по `selDate`.

### Связь с доской — одно централизованное правило в API `PATCH /tasks/:id`

Чтобы Обзор ⇄ канбан ⇄ Свод были согласованы через единственный источник `startDate`:

- если в патче `status` меняется на `inprogress` и `startDate` в теле не передан → сервер ставит `startDate = сегодня` (взял из Бэклога в «В работе» на доске → упало в сегодняшний Обзор);
- если `status → done` → сервер ставит `doneAt = now()`;
- если `status → inprogress` из `done` (reopen) → `doneAt = null` (и startDate=сегодня по правилу выше — задача возвращается в сегодняшнюю работу).

Это правило централизует связь: и доска (drag между колонками), и Обзор (чекбокс), и любой другой путь дают одинаковый результат. `backlog` `startDate` не трогает (задача остаётся в пуле, из списка дня её убирает фильтр по статусу).

### Данные

Миграция не нужна. Используются существующие поля `Task`: `status` (`TaskStatus`), `startDate` (`DateTime @default(now())`), `doneAt` (`DateTime?`), `assigneeId`. Индекс `@@index([assigneeId, startDate])` уже есть.

### Затрагиваемые файлы

- `apps/api/src/routes/tasks.ts` — правило переходов статуса в PATCH (startDate/doneAt); POST принимает `status` + `startDate` (проверить, что уже принимает).
- `apps/web/src/pages/DashboardPage.tsx` — `dayTasks` фильтр; payload inline-создания (`status:'inprogress'`, `startDate:selDate`); `doneMut` тоггл `done↔inprogress`.

### Тестирование

- **API** (`apps/api/src/routes/tasks.test.ts`, новый или дополнение): PATCH `status→inprogress` без startDate ставит сегодня; `status→done` ставит doneAt; reopen `done→inprogress` чистит doneAt; `backlog` startDate не трогает.
- **Браузер**: создать задачу в Обзоре → она в «В работе» на доске; отметить готово → зачёркнута, осталась; переключить день → её нет; вернуть день → на месте; на доске перетащить бэклог→в работе → появилась в сегодняшнем Обзоре.

### Согласованность (правило Nexus)

Единый источник дня — `startDate`. Свод (`routes/svod.ts`) считает задачи по `startDate` → задача, взятая в работу сегодня, попадает в сегодняшнюю ячейку Свода. Обзор, канбан, Свод не расходятся.
