# Design: Project Rename & UX Improvements

**Date:** 2026-04-19  
**Status:** Approved

## Context

The app previously used "матрица" as the primary concept for a top-level production entity. Going forward:

- **Проект** = `MatrixRegistry` (was "матрица") — the top-level entity
- **Смена** = `StatusRow` (unchanged in DB) — individual shifts within a project

DB table names are NOT renamed (too large a scope). Only UI labels and one schema change (multi-select unit).

---

## 1. UI Label Renames

All occurrences of "матрица" in user-facing strings are replaced with "проект":

| Before | After |
|--------|-------|
| `+ Создать матрицу` | `+ Создать проект` |
| `Новая матрица` (form title) | `Новый проект` |
| `Редактировать матрицу` (form title) | `Редактировать проект` |
| `Реестр матриц` (section header) | `Реестр проектов` |
| Drive error: "Матрица создана, но ошибка Drive…" | "Проект создан, но ошибка Drive…" |

---

## 2. Create/Edit Project Form (`MatrixFormModal`)

### Status field
- Removed from form as an editable `<select>`
- Replaced with a static badge at the **top** of the form
  - On **create**: always shows `Запрос`
  - On **edit**: shows the project's current status (read-only; edit via project card)
- Status is only editable inside the project card (Info tab → Description block)

### Name preview block
- The block showing `Матрица v4.1: клиент: название: дата` is **removed entirely**
- The `name` field stored in DB will be auto-generated on backend as `{client} — {projectName}` (no version, no date)

### Business unit (multi-select)
- Current: single `<select>` bound to `unit: string`
- New: custom dropdown with checkboxes, bound to `unit: string[]`
- Displays selected values as comma-separated text in the trigger button
- Options sourced from КФПД column 5 (same as before)

## 4. Info Tab — Description Block (`RegistryInfoTab`)

### Removed
- Row "Название" (duplicates header)
- Row "Клиент" (duplicates header)

### Added
- Row **Ссылка на КП** — rendered as a clickable `<a>` link (same style as existing KP link in "О проекте" card). Shown only if `entry.kpLink` is set.
- Row **Статус** — `<select>` with all project statuses. On change: immediately fires `PATCH /internal-matrix/:id` with `{ status }`. On success: invalidates `['internal-matrix']` query → header updates automatically. No separate save button.

### Unchanged
- `<textarea>` for `brief` (project description). Keeps its own save button since it's free text.

## 6. DB Migration — `unit: String → String[]`

**Schema change** (`packages/db/prisma/schema.prisma`):
```prisma
// MatrixRegistry model
unit  String[]  @default([])
```

**Migration SQL** (auto-generated by Prisma, plus data migration):
```sql
-- Convert existing non-null unit values to single-element arrays
ALTER TABLE "matrix_registry" ALTER COLUMN "unit" TYPE TEXT[] USING
  CASE WHEN "unit" IS NULL OR "unit" = '' THEN '{}'::TEXT[]
       ELSE ARRAY["unit"]
  END;
ALTER TABLE "matrix_registry" ALTER COLUMN "unit" SET DEFAULT '{}';
ALTER TABLE "matrix_registry" ALTER COLUMN "unit" SET NOT NULL;
```

**API changes:**
- `POST /internal-matrix` — accepts `unit: string[]`
- `PATCH /internal-matrix/:id` — accepts `unit: string[]`
- `GET /internal-matrix` — returns `unit: string[]`
- `GET /internal-matrix/by-client/:client` — returns `unit: string[]`

**Frontend form state:**
- `unit: string[]` (was `string`)
- Serialized as-is in request body
