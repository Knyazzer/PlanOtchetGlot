# Кабинет сотрудника — целевое решение (со слов Влада 2026-08-02)

> Проектируем цельный функционал рядового сотрудника поверх существующих инструментов (аудит `2026-08-02-employee-cabinet-audit.md`). Опирается на решения по календарю `2026-08-02-calendar-mechanics-decisions.md`.

## Решения (зафиксировано)
- **Гейт `canAccessPlatform` — НЕ трогаем** (бета-выдача остаётся). Проблема не в нём; задача — **функционал сотрудника внутри платформы**.
- **Пункт меню «Пульс» (переименован с «Главная») = пульс компании.** Обзорный экран: **новостная лента** (посты), кто сегодня работает (по статусам присутствия), глобальные статусы/дедлайны/активность, м.б. лёгкая аналитика. Оживляем 4 текущие заглушки `HomePage`.
  - **Новостная лента = посты, как главный канал в Telegram:** право **публиковать пост** выдаётся отдельным людям (HR/PR/руководство — через модуль/флаг), **читают все**. Нужна модель `Post`/`News` (автор, дата, текст, вложения, закрепление) + право `news.publish` (или роль). Полноценная фича — бэкенд + UI-редактор поста.
- **«Мой кабинет» = рабочий стол сотрудника.** ВСЯ его работа: **план дня (задачи со временем)**, мои задачи (сегодня/ближайшие), дедлайны, события, мой статус, быстрые действия (создать задачу/событие, заявка на отпуск/статус). План дня по задачам — здесь.
- Пульс и Мой кабинет — **две разные страницы** (не сливаем).
- **«Мой кабинет» = контейнер с внутренними вкладками `[Обзор | Задачи]`** — «Задачи» уехали из верхнего меню внутрь кабинета (Обзор = рабочий стол; Задачи = полный TasksPage). ✅ сделано (`743a283`).
- **Единый статус (B) — да:** свести `dayFormat` ↔ присутствие ↔ `profile.status` в **одну сущность статуса** (конфигурируется HR, §3 календарной спеки), авто-простановка по рабочим часам; кормит Главную («кто работает»), Команду, Свод.
- **Отчёт (D) — да:** свой Свод + Аналитика (свой скоуп), кормятся согласованно с новой моделью, без дублей.

## Экраны

### Пульс (меню «Пульс», бывш. «Главная») — пульс компании
- **Новостная лента (посты)** — как главный канал в Telegram: публикуют избранные (право `news.publish`), читают все. Модель `Post`/`News` + UI-редактор + закрепление.
- **Кто сегодня работает** — из единого статуса присутствия (офис/удалёнка/на проекте/отсутствует), группировка по отделам; «helicopter-lite» для всех.
- **Статусы и дедлайны / активность** — глобальные важные дедлайны, ближайшие общие события/мероприятия, кто в отпуске/командировке (полосы HR).
- Роль экрана — обзор компании, НЕ личные задачи (те — в Мой кабинет).

### Мой кабинет — «Рабочий стол»
- **Мой статус сегодня** (виджет) — единый статус: показать/сменить (в работе/удалёнка/на проекте/…); авто-простановка.
- **План дня** — задачи со временем + события на сегодня, тайм-лайн дня (мини день-вью календаря), заполнение плана (переезд логики `DayFillCard`/`day-entries` сюда, согласованно со Сводом).
- **Мои задачи** — сегодня + ближайшие (мои/назначенные мне), быстрое «сделано», создать задачу.
- **Дедлайны** (1/3/7 дн).
- **Мои заявки** — отпуск/статусы (создать заявку на отпуск → §4 календарной спеки).
- **Быстрые действия** — + задача, + событие, заявка на отпуск.

## Декомпозиция (реализация по шагам, каждый — с визуальной сверкой Влада)
1. **Мой кабинет → рабочий стол** — реорганизация `DashboardPage` под канон ui-kit: план дня + задачи + дедлайны + события + виджет статуса + быстрые действия. Фронт, существующие API. *(старт — самый видимый, низкий риск)*
2. **Единый статус** — модель (свести `dayFormat`/`profile.status`), авто-простановка по рабочим часам, UI-виджет, HR-конфиг списка. Backend/модель — фундамент для «кто работает».
3. **Пульс** — новостная лента (модель `Post` + право `news.publish` + редактор + закрепление), «кто работает» из §2, глобальные дедлайны/мероприятия, лёгкая аналитика. Оживить заглушки `HomePage`.
4. **Согласование план-дня ↔ календарь-день ↔ Свод** — единая модель заполнения дня (вместе с треком календаря).
5. **Заявка на отпуск + заявление** (§4 календарной спеки) — воркфлоу + PDF-форма.

## Открытые вопросы (по ходу)
- **Новости компании** — источник/кто постит (отдельная сущность? HR/админ-редактор?).
- **Единый статус vs dayFormat** — сливаем в одно поле или статус присутствия = отдельный слой над форматом дня (формат = «тип дня для отчёта», статус = «где я сейчас»)? Уточнить при шаге 2.
- Старт — шаг 1 (Мой кабинет), рекомендую.
