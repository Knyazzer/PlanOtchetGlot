## 1. Кабинет сотрудника / «Мой рабочий день»
- ✅ Структура: **Пульс** (главная-лента), **Мой кабинет** = рабочий стол, 3 вкладки [Обзор · Задачи · Треки].
- ✅ **Месячная сводка справа** (`MonthStrip`): весь месяц вертикально, кубик = тип дня; клик → **дате-зависимый кабинет** (задачи/план/события на выбранную дату, планирование на будущее); кнопка «← Сегодня».
- ✅ **«Мой рабочий день»**: тип дня из графика (руками не выбираем), **большая кнопка Начать/Закончить + крупный живой таймер**, автосейв (без «Сохранить»), время правится вручную; кнопка всегда видна (дизейбл когда нельзя).
- ✅ **Баланс часов**: дельта к норме дня (недо/переработка) + месячный баланс (отработано/норма/баланс).
- ⏳ **Запас часов за произвольный период** (сейчас только текущий месяц) — где перегруз/недогруз по дням.
- ✅ **Самостоятельный статус**: больничный/отпуск сотрудник ставит сам; тип офис/удалёнка — из графика.
- ⏳ **Месячная вертикальная сводка план-отчёта** в кабинете (как в TVonly) — частично закрыто MonthStrip.

## 2. График работы (HR)
- ✅ Модель `WorkSchedule` (недельный паттерн типов дня + часы) → «тип дня по умолчанию» (подсказка, НЕ факт).
- ✅ HR-конфиг графика в карточке сотрудника (`WorkScheduleEditor`, автосейв).
- ✅ Форматы дня: базовый набор 6 (Выходной/Офис/Удалёнка/Больничный/Командировка/Отпуск); **HR добавляет свои** (отгул, за свой счёт) через справочник; HR-доступ к справочнику дан.
- ✅ **Единый статус/присутствие** (`presence`): работает/закончил/отсутствует/по графику/выходной — из факта дня + графика.
- ⏳ **Заявка на отпуск** — из кабинета → согласование руководителем → полоса в календаре; больничный сам; **скачивание заявления (PDF-форма)** с реквизитами.
- 🧭 Список статусов присутствия конфигурируется HR (не хардкод) — «редактировать список статусов компании».

## 3. Календарь
- ✅ Виды месяц/неделя/день; события `Event` (meeting/task/personal); общие `CalendarEntry` (Знаменки/HR).

- 🧭 **Иерархия календарей (§7)**: личный / общий компании / проектный (видишь «свои» мероприятия) / календарь встреч / HR-статусы / **локации (Знаменки) — бронь ТОЛЬКО через проект** (+ лёгкий «бронь/внутренний проект» с мини-брифом).

## ⚠️ ЗАЛОЖИТЬ СЕЙЧАС (пустые розетки — иначе болезненная миграция на живой системе)
> Из ECOSYSTEM §9А + STRATEGIC §3. Добавить nullable-поля/каркасы БЕЗ реализации логики:
- `Task`: `source`, `externalId`, `externalUrl`, `kind`(task|meeting), поля времени/занятости, **`goalId`**.
- **Внешний источник уведомления** (не только свой TaskLog) — поле-заготовка.
- **Каркас service-account** аутентификации (приём событий от внешних продуктов) — заложить, не строить.
- **Свод/отчёт держать ВЫЧИСЛЯЕМЫМ** из задач (не отдельная таблица) — ради будущего авто-отчёта.

## 🚫 Чего НЕ делать (грабли ECOSYSTEM §9Б)
Не делать жёсткую ручную схему отчёта (2 колонки); не хардкодить «уведомления только из TaskLog»; не завязывать задачу на «один день/бинар»; не ломать схемную изоляцию БД.

## Крупные/неочевидные требования (легко потерять) — полный список
1. **Пустые розетки — заложить nullable-поля сейчас** (блок выше). Пропуск = миграция на живой системе.
2. **Инвариант неизменяемости истории** — сквозной: закрытый период целей read-only; снапшоты divisionId/deptId при реорганизации; график HR не влияет на прошлые DayEntry; Свод считает только реальные DayEntry.
3. **Бронь локаций (Знаменки) ТОЛЬКО через проект** — лёгкий «бронь/внутренний проект» с мини-брифом; проекты «из одного человека» — ОК.
4. **Тип дня — НЕ выбор сотрудника, а график HR** (ревизия 2026-08-04): сам ставит только больничный/отпуск, командировка — из проекта, остальное — руководитель.
5. **Единый статус** vs `dayFormat` vs `profile.status` — сейчас два несвязанных; свести в одну сущность, конфигурируемую HR (не финализировано).
6. **Гейт `canAccessPlatform` активен в проде** (CLAUDE.md пишет «снят» — расхождение). Дефолтный сотрудник платформу НЕ видит — нужно продуктовое решение по роллауту.
7. **Форма роли пишет реальную оргструктуру** (не свободный текст): реконсиляция связей, конфликт слота head/director (409+replace), совмещение до 2 назначений.
8. **Баланс часов** — дельта к норме графика + накопленный запас за период (где перегруз/недогруз), не просто «X ч».
9. **Helicopter-view руководителей** — видят календари/загрузку подчинённых без переключения.
10. **Overlap-раскладка**: деградация по числу параллельных (неделя ~3, день ~20) + создание параллельного drag'ом в зазоре справа.
11. **Drag-интерактив без затемнения** (пунктир/заливка/силуэт, двусторонняя связь края↔карточка).
12. **Свод/отчёт ВЫЧИСЛЯЕМЫЙ** из задач (запрет отдельной таблицы).
13. **Support-чат сквозной на компанию** — уведомления только техподдержке, решения публично видимы.
14. **Многодневность/all-day — только HR-слой** (`CalendarEntry.endDate`, не N экземпляров); удалёнка = режим присутствия (без полосы).
15. **PWA deep links + protocol handler** (`web+nexus://`, `#chat/42/message/1007`) как канал обмена — с проверкой прав.
16. **Заявление на отпуск — PDF-форма** для печати/подписи (не только цифровой воркфлоу).
17. **ТВ-департамент / производственный календарь эфирных бригад** (модель PlanOtchetTVonly) — сильно другая, отложена, зафиксирована.
18. **Иерархия «большая задача → дневные под-этапы»** (не бинар), перенос незакрытого — эволюция план-отчёта.
19. **Автосохранение везде** (debounce, убрать «Сохранить») — правило (уже DayFillCard/WorkScheduleEditor).
20. **Чаты → канон kanban** + дореализация бэкенда (реакции/ответы/избранное — заготовки в схеме есть).
21. **Nexus = слой сведения экосистемы** (Nexus зеркалит read-only, правка → deep-link в продукт).
22. **Персонал-сплит** (таблица+карточка) — растёт число настроек.
23. **Дробление god-файлов** (TasksPage ~1600, ChatsPage ~1375, ProjectsPage ~1170) + восстановление тест-покрытия.
