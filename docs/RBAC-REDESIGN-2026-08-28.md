# Спека: редизайн ролевой модели Nexus + идеология «доступ → UI»

> Статус: **черновик на вычитку Влада** (2026-08-28). Родитель — [../CLAUDE.md](../CLAUDE.md) (Auth и RBAC). Основание — разговор с Владом + аудит модулей (грепом по коду). Заменяет/дополняет `docs/RBAC-MODEL.md` в части UI и каталога.

## 1. Проблема (текущее состояние)

- **Страница «Роли и доступы»** (админ) — плоская простыня департаментов друг под другом, без описаний. Непонятно, что значит каждый чекбокс и где он проявляется.
- **4 из 15 модулей — рудименты** (grant = 0 эффекта): `prod.board` (Доска производства), `com.clients` (Клиенты), `com.workitems` (Workflow заявок), `adm.svod-company` (Свод·компания). В коде не потребляются.
- **Группа «Администрация» — свалка**: аналитика + свод + календарь + пульс — 4 разные области под одним ярлыком. `group`-поля не совпадают со смыслом.
- **Механика `extraModules` порочна**: модуль → **отдельный пункт меню** (так родились фантомные «Публикация в Пульс»/«Доска производства», и «Оргструктура»→вся админ-страница «Персонал»). Право не должно плодить вкладки.

## 2. Принципы

### ⛔ 2.1 Идеология «доступ → UI» (главное правило)
Право расширяет **существующую** функцию — и показывается **в её же вкладке**, а не заводит новую:
- «редактировать Пульс» → кнопка редактирования **на Пульсе**;
- «видеть оргструктуру/данные всей компании» → **переключатель департаментов в существующей «Команда»** (или соответствующей странице);
- «ставить встречи в общий календарь» → выбор календаря при создании события **в существующем Календаре** — просто на один календарь больше.

**Новая вкладка — только для принципиально НОВОГО функционала**, которому нет дома. Кандидат: HR-аналитика (графики/подсчёт отпусков-больничных) — но, вероятно, это часть **Аналитики**, а не отдельная вкладка. Решать у конкретной фичи.

Проверка при выдаче любого нового права: «расширяю существующую функцию или добавляю новую?» → в первом случае ищем её вкладку, во втором (редко) — обосновываем новую.

### 2.2 Least-privilege + прозрачность
- Показывать только то, что роль реально может (детали — [[nexus-constrain-user-least-privilege]]).
- У каждого чекбокса на «Роли и доступы» — **описание**: что даёт и где отображается.

## 3. UI страницы «Роли и доступы» (мастер-детейл)

Как «Плееры» в support: **слева — список департаментов** (переключатель), **справа — полная матрица модулей** выбранного департамента.
- Матрица сгруппирована по **областям** (см. §4), не по старым `group`.
- Каждый модуль-строка: название · уровень (просмотр / сотрудник+ / руковод+) · **иконка-подсказка с описанием** (что значит, где проявляется).
- Наверху департамента — счётчик «N чел · M активных модулей».
- Пустые/рудиментные модули на странице не показываем (после чистки §4).

## 4. Каталог модулей — очищенный и перегруппированный

### Область «HR / Персонал»
| Модуль | Что даёт | Где отражается |
|---|---|---|
| Оргструктура (`hr.orgstructure`) | правка оргструктуры/графиков, доступ HR к данным персонала | **в «Команда»** (управление/редактор), сделано — не отдельная «Оргструктура» |
| Отсутствия сотрудников (`hr.absences`) | **ПРОСМОТР** сводки отсутствий по компании (у кого сколько отпусков/больничных/отгулов, даты, кто согласовал, статусы заявок). Отсутствия создаются через **Заявки** (сотрудник→руководитель→согласование), НЕ вручную HR | **Аналитика** (people-analytics, company-scope для HR) |

> **Модель «аналитика по людям» (отсутствия/HR-статистика) — с ролевым охватом, во вкладке «Аналитика», не отдельной вкладкой:**
> сотрудник → только свои статусы (сколько/когда отпусков/болезней/дней); руководитель → своя команда; директор → свой департамент; HR (`hr.absences`) → вся компания. Текущий код `hr.absences` гейтит запись hr-записей в календарь + форматы дня — это **рудимент/переработка**: реальная семантика = company-охват people-аналитики. Часть эпика HR-модуль.

## 5. Переход механики `extraModules`

Сейчас: `AppShell.extraModules` превращает модуль в пункт меню (порождает фантомы). 
Целевое по идеологии §2.1:
- **Убрать** «модуль → новый пункт меню» для всех, кроме сервис-модулей (`ext.*`/`int.*` — переход во внешний продукт).
- Право отражать **внутри существующей вкладки**: кнопка/переключатель/выбор, гейтится `hasModule(...)` в нужном месте, а не отдельным навигационным входом.
- `hr.orgstructure`: перестать открывать всю «Персонал»; доступ к оргструктуре — через «Команда» (переключатель департаментов), правка персонала остаётся admin-only.

## 6. Этапы реализации (черновик)
1. **Чистка реестра** (быстро): удалить рудименты (по решению §4), перегруппировать `group` по областям. Обновить `RBAC-MODEL.md` и сид.
2. **UI «Роли и доступы»**: мастер-детейл (департаменты слева, матрица справа), описания модулей.
3. **Механика доступ→UI**: убрать `extraModules`-вкладки (кроме сервис-модулей); отразить права внутри вкладок (Пульс-кнопка, Команда-переключатель, Календарь-выбор, Аналитика-scope). Убрать `hr.orgstructure`→полная «Персонал».
4. **Точечные подключения** (если решим оживлять): `com.clients` → доступ к /clients по модулю; `adm.svod-company` → company-Свод в svod.ts.
