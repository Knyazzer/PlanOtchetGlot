## Зафиксированные решения (вход в план)

- Объём: **ядро поэтапно** — структура + задачи + DayEntry/Свод сначала.
- Модель досок: кастомизируются **только личные** доски; отдел/проект — колонки по `status`.
- Свод: v1 мягкое планирование, схема с заделом под табель (`lockedAt`).
- Переход: **жёсткий cutover**, разовый ETL.
- Фронт-стек: запрет UI-библиотек снят. Дом-кит **Tailwind + shadcn/ui (Radix) + recharts + lucide**, визуальный эталон — Figma-макет `.figma/ux-ui prototype/`.
- Проекты — нативная модель Nexus (`Client→Project→WorkItem→Track`), реестр донора не воспроизводим.
- sales-CRM — вне скоупа. Redis — отложен.

## Рабочий протокол (из RULES.md/CLAUDE.md)

- Одна фича за раз: **backend → тест → frontend → браузер → следующая**.
- Definition of Done на каждую задачу: `pnpm --filter @nexus/api build` (0 ошибок) · `pnpm --filter @nexus/web exec tsc --noEmit` (0) · `pnpm test` (зелёные) · ручная проверка в браузере.
- Каждый `useMutation` инвалидирует затронутые запросы; многопользовательские страницы — polling.
- Роуты: Zod `.safeParse`, `preHandler` auth/requireRole, тест `*.test.ts` рядом, обновить таблицы в CLAUDE.md.

## ЭТАП 4 — Cutover

> Боевой ПланОтчет **откатился к стабильной версии** и больше не развивается. Нормализованный

> - **Дни** — `pr_e_<div>_<date>_<emp>` с полями `dayFormat/startTime/endTime/breakMin` —
>   **формат НЕ менялся**, `extract.py` читает их как есть. Свежие данные: 1 мая → 28 июня 2026.
> - **Задачи** снова **внутри дней** (`pr_e_*.tasks[]`): `id, client, project, name, type, timeMin, done, kanbanCol`.
>   Поля беднее v2 (нет раздельного план/факт — только `timeMin`; нет дедлайна/описания/`assigneeId`
>   — исполнитель и дата выводятся из ключа дня).
> - **Структура** — `pr_structure` (департамент→divisions→employees вложенно), а не `pr_v2_*`.
> - **Проекты/клиенты/алиасы** — `pr_projects` (5), `pr_clients` (7), `pr_project_aliases` (11).

### Стратегия переноса данных — ГИБРИД (утв. владельцем 2026-06-11)

Принцип: **дни и задачи имеют разную ценность во времени.** День — факт отчётности (ценен
навсегда: Свод/Аналитика). Задача — операционка (прошлая закрытая задача мертва; ценен только
незакрытый хвост).

| Слой | Решение | Объём в снапшоте |
|------|---------|------------------|
| **Дни** (формат/часы/баллы) | переносим **всю историю** | 1444 дня с форматом |
| **Закрытые задачи** | **не переносим** (мертвы) | 6520 |
| **Незакрытые хвосты** | **точечно в Личном кабинете**: список «Хвосты из ПланОтчета — перенести?», галочками; создаются как **обычные** задачи Nexus (редактируемые/закрываемые) | 329 прошлых + 67 будущих, у 41 чел (≈8/чел) |

Отвергнутые варианты: чистый старт без задач (плохой первый день — человек теряет 8 недоделок);
read-only «статичный визуал» старых задач (костыль: вариативные поля по периодам, неясно как закрывать).

Маппинг хвоста: `timeMin → plannedMinutes` (факта ещё нет), `client/project/type/name` — как есть,
дата хвоста = дата дня (или дата переезда), исполнитель = владелец дня.

### Шаги cutover
1. **Адаптировать `extract.py` под новую структуру**: дни (как есть) + структура из `pr_structure`
   + проекты/клиенты/алиасы из `pr_*`. Задачи массово НЕ грузим.
2. **Импорт-хвостов** — отдельный механизм: при онбординге/в Кабинете показать сотруднику его
   незакрытые задачи из снапшота, перенести выбранные как задачи Nexus.
3. **Свежий снапшот** на день X: `curl https://planotchet.ru/api.php -o snapshot.json` (пока прод
   отдаёт без секрета; при деплое их auth — понадобится `X-Secret`).
4. Валидация: счётчики дней/сотрудников, суммы минут, отсутствие висячих FK.
5. Выдача логинов (Supabase auth), переключение пользователей.
6. Донор → read-only (заодно закрыть открытый доступ к `/api.php`).
