# Модуль «Проекты» — план разработки и инструкция для продюсера

---

## Концепция

Модуль «Проекты» — это производственный реестр. Каждый проект — это контракт с клиентом.
Внутри проекта живут **Work Item** (WI) — конкретные съёмки или задачи.
Каждый WI раскладывается на **треки** отделов, а треки — на **задачи** исполнителей.

```
Клиент
  └─ Проект (КП, бриф, продюсер)
        └─ Work Item (съёмка, дата, формат, локация)
              ├─ Роли: исп. продюсер / лайн-продюсер / аккаунт-менеджер
              ├─ Отделы: кто участвует (монтаж, графика, звук, ...)
              ├─ Треки отделов (план работы каждого отдела)
              │     └─ Задачи исполнителей
              └─ Расходы (смета, фактические затраты)
```

---

## Инструкция для продюсера

### 1. Создать клиента

Клиенты импортируются из таблицы **КФПД** (столбец A).

1. Открыть **База данных** (левое меню, только для администратора)
2. Найти карточку **К/Ф/П/Д**
3. Нажать **↻ Обновить** — данные загрузятся из Google Sheets
4. Нажать **⬆ Импортировать в БД** — клиенты появятся в системе

Или добавить клиента вручную — в разделе «Проекты» при создании проекта есть поле «Клиент» с выпадающим списком и опцией «+ Новый клиент».

---

### 2. Создать проект

1. Открыть раздел **Проекты** в левом меню
2. Нажать **+ Новый проект**
3. Заполнить:
   - **Название** — рабочее название проекта
   - **Клиент** — выбрать из списка
   - **Ссылка на КП** — URL коммерческого предложения (Google Docs / Диск)
   - **Бриф** — краткое описание задачи
4. Статус по умолчанию — **Черновик**. Менять статус по мере работы:
   - `Черновик` → проект на согласовании
   - `Активный` → в производстве
   - `Готово` → сдан
   - `Отменён` → отменён

---

### 3. Создать Work Item (съёмку/задачу)

Work Item — это конкретная единица производства: один съёмочный день, один ролик, один выпуск.

1. Открыть проект → нажать **+ Work Item** в правой панели
2. Заполнить:
   - **Название** — например «Съёмка. Интервью CEO. 15 мая»
   - **Дата** — дата съёмки или дедлайн
   - **Формат** — вертикаль, горизонталь, сторис, прямой эфир и т.д.
   - **Локация** — место съёмки
   - **Описание** — дополнительный контекст
3. После создания назначить **роли**:
   - **Исп. продюсер** — ответственный за производство
   - **Лайн-продюсер** — операционное управление
   - **Аккаунт-менеджер** — связь с клиентом
4. Установить **статус WI**:
   - `Запрос` → поступил запрос, не подтверждён
   - `Активный` → в работе
   - `Готово` → сдан клиенту
   - `Отклонён` / `Отменён`

---

### 4. Подключить отделы к Work Item

> ✅ **Реализовано.**

Каждый WI имеет список задействованных отделов (из справочника структуры компании).
В детальной панели WI есть секция **«Отделы»** с чекбоксами — продюсер отмечает,
кто участвует: монтаж, графика, звук, режиссура, операторский и т.д.
Сохранение через `PUT /work-items/:id/departments` (модель связи `WorkItemDivision`).

> ⏳ **Не реализовано (будущая итерация):** авто-создание трека для подключённого
> отдела и автоматическое назначение руководителя трека (тим-лид отдела).

---

### 5. Создать трек отдела и поставить задачи

Трек — это план работы одного отдела в рамках WI.

**Сейчас** (текущая реализация):
1. Перейти в раздел **Задачи → вкладка Треки**
2. Нажать **+ Новый трек**
3. В поле **«Привязать к Work Item»** выбрать нужный WI из проекта (форма трека отправляет `workItemId`)
4. Добавить участников трека — сотрудников отдела
5. Создать **этапы** трека (опционально): пре-продакшн → съёмка → постпродакшн
6. Внутри трека создать **задачи** с дедлайнами и исполнителями

**После привязки трека к WI** продюсер видит (✅ реализовано):
- В карточке WI — секция **«Треки»** со списком треков и прогресс-баром по каждому
  (`GET /work-items/:id` возвращает привязанные треки)
- Сводный прогресс по WI = среднее по всем трекам

---

### 6. Отслеживать прогресс по проекту

**Сейчас** — в детальной панели проекта:
- Список WI со статусами
- Количество треков на каждый WI

**Вкладка Workflow** (✅ реализовано):
- Сводная таблица всех WI по всем проектам (`GET /work-items`)
- Фильтры: по статусу / отделу / продюсеру / дате
- Прогресс-бар по каждому WI (из задач треков)

> ⏳ **Не реализовано:** экспорт в CSV.

---

### 7. Финансовая аналитика и расходы

> ⚠️ **Частично реализовано** — базовый учёт бюджета и расходов есть, аналитика — в разработке.

**На уровне Work Item:**
| Поле | Описание | Статус |
|------|----------|--------|
| Бюджет WI | Сумма, утверждённая с клиентом | ✅ поле `budget` (Decimal) |
| Смета | Плановые затраты по статьям | ⏳ в разработке |
| Фактические расходы | Что реально потрачено | ✅ модель `Expense`, CRUD |
| Маржа | Бюджет − Факт | ⏳ в разработке |

**Статьи расходов** (enum `ExpenseCategory`, ✅ реализовано):
- `equipment` — Оборудование / аренда
- `transport` — Транспорт / логистика
- `fees` — Гонорары (внешние)
- `postproduction` — Постпродакшн (внешний)
- `other` — Прочее

**Как добавлять расход** (✅ реализовано — секция «Финансы» в карточке WI):
1. Открыть WI → секция **Финансы**
2. Указать бюджет через `BudgetInput`
3. Добавить расход: сумма, статья, дата, комментарий
4. Система показывает сравнение **Расходы / Бюджет**

API: `POST/PATCH/DELETE /work-items/:id/expenses`, `PATCH /work-items/:id` (поле `budget`).

> ⏳ **Не реализовано (в разработке):** смета / плановые затраты, расчёт маржи,
> графики расходов по времени, разбивка по статьям (pie chart), прикрепление
> документов к расходам, рентабельность по клиенту / по типу продукта.

## Технический стек (для разработчиков)

**Схема БД:** `Client → Project → WorkItem → Track → Task`

**API:**
- `GET/POST /projects` — список и создание проектов
- `GET/PATCH/DELETE /projects/:id` — работа с проектом
- `POST /projects/:id/work-items` — создать WI в проекте
- `GET/PATCH/DELETE /work-items/:id` — работа с WI
- `GET /clients` + `POST /clients/bulk-import` — справочник клиентов

**Ключевые поля WorkItem в БД:**
```
id, projectId, title, description, status,
execProducerId, lineProducerId, accountManagerId,
date, format, location,
budget (Decimal),
createdAt, updatedAt
```

**Связи WorkItem:**
```
departments — WorkItemDivision[] (подключённые отделы)
expenses    — Expense[] (расходы по статьям)
tracks      — Track[] (привязанные треки)
```

**Поля Track (связь с WI):**
```
workItemId  — опциональная привязка к WI
```
