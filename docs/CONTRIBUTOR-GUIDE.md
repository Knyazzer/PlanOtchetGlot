# Руководство контрибьютора — ветка `daewoo-matiz`

> Документ для внешнего разработчика. Читай целиком перед началом работы.

---

## Твоя ветка

```
master          ← прод (nexus.megapolis.media) — не трогать
└── rebuild-v4  ← основная ветка разработки (сюда PR от всех)
      ├── knyazzer      ← ветка ведущего разработчика
      └── daewoo-matiz  ← ТВОЯ ветка
```

**Правило:** все изменения делаешь в `daewoo-matiz`. Когда готово — открываешь Pull Request в `rebuild-v4`. Ничего напрямую в `rebuild-v4` или `master` не пушишь.

---

## Стек проекта

- **Backend:** Fastify (Node.js/TypeScript), порт 4000 — `apps/api/`
- **Frontend:** React + Vite, порт 5173 — `apps/web/`
- **БД:** PostgreSQL + Prisma, порт 5433 (dev) — `packages/db/`
- **Пакетный менеджер:** pnpm (монорепо)
- **Деплой:** push в `master` → GitHub Actions → Docker → VDS автоматически

---

## Запуск локально

### 1. Зависимости

```bash
pnpm install
```

### 2. БД в Docker

```bash
docker compose -f docker-compose.dev.yml up -d
```

### 3. Миграции + сид

```bash
pnpm --filter @nexus/db exec dotenv -e ../../.env -- prisma migrate deploy
pnpm db:seed
```

> Сид создаёт: `admin@nexus.local` и `user@nexus.local`. В dev входишь **без пароля** — просто вводишь email, пароль любой.

### 4. Серверы

```bash
.\start.ps1       # Windows — открывает два окна (API + Web)
# или
pnpm dev          # один терминал
```

Проверка: открой http://localhost:5173, войди как `admin@nexus.local`.

## Актуальные данные донора (для тестирования Свода и Аналитики)

Чтобы Свод и Аналитика показывали реальные данные, нужен дамп из ПланОтчет.

**Свежий снапшот:** `curl https://planotchet.ru/api.php -o snapshot.json`

Залить в БД:
```bash
cd c:\scripts\planotchet   # репо ETL-скриптов
python extract.py --input snapshot.json --target-db postgresql://tvshifts:tvshifts_pass@localhost:5433/nexus_dev
```

> Без этого шага Свод/Аналитика за май 2026 будут пустые. Для проверки UI-механик дамп не обязателен.

## Что нужно проверить (сценарии приёмки)

Полный чеклист: [`docs/ACCEPTANCE-CHECKLIST.md`](./ACCEPTANCE-CHECKLIST.md)

Краткий маршрут:

### Сценарий 1 — Обычный сотрудник (member)
Войди как `user@nexus.local`:
- [ ] Главная: карточка «Заполнить сегодня» — выбрать формат, сохранить
- [ ] Задачи: создать задачу с повтором «По будням» → на доске появились экземпляры
- [ ] Свод: видит только свой отдел, чужой → «Нет доступа»
- [ ] Аналитика: скоупы «Я» и «Команда» работают; «Компания» недоступна
- [ ] Настройки: только вкладка «Профиль и тема»

### Сценарий 2 — Админ
Войди как `admin@nexus.local`:
- [ ] Персонал → Структура: назначить руководителя отдела
- [ ] Настройки → Роли и доступы: снять/вернуть модуль → у сотрудника меняется сайдбар
- [ ] Настройки → Форматы дня: изменить балл → в Своде за май НЕ изменился (версионирование)
- [ ] Свод: видит все отделы; Аналитика «Компания» доступна

### Сценарий 3 — Мобильная версия (сузить браузер <768px)
- [ ] Нижняя навигация: Главная · Задачи · Свод · Чаты · Ещё
- [ ] Свод = лента «Мои дни», не сетка
- [ ] «Ещё» открывает остальные разделы

## Что можно делать в своей ветке

✅ Фиксить баги из чеклиста  
✅ Улучшать UI-детали (отступы, цвета — строго из `docs/DESIGN.md`)  
✅ Добавлять тесты  
✅ Рефакторинг без изменения поведения  

❌ Не добавлять новые зависимости без согласования  
❌ Не менять схему БД (Prisma schema) без обсуждения  
❌ Не трогать `.env`, `docker-compose.prod.yml`, CI/CD  
❌ Не пушить напрямую в `rebuild-v4`, `knyazzer`, `master`

## Как открыть Pull Request

1. Запушь изменения в свою ветку:
   ```bash
   git add .
   git commit -m "fix: описание что исправил"
   git push origin daewoo-matiz
   ```

2. На GitHub открой PR: `daewoo-matiz → rebuild-v4`

3. В описании PR укажи:
   - Что исправил / добавил
   - Какой пункт чеклиста закрывает
   - Если менял UI — скриншот до/после
