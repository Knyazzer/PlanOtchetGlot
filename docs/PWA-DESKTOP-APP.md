# PWA — установленное веб-приложение (десктоп/мобилка): возможности и механики

> Справочник по технологии PWA для экосистемы Nexus/Megapolis. Записан по итогам обсуждения
> (2026-08-02). Цель — единый список того, что умеет установленное веб-приложение, чтобы опираться
> при разработке. Приоритет применения: **в первую очередь Nexus**, во вторую — support (минимально:
> кастомизация отображения/UI в режиме приложения). Наши веб-приложения — React+Vite; всё ниже
> работает и в браузере, и в установленном PWA (в PWA — удобнее: своё окно, пуши, иконка, бейдж).

## 1. Что это и кроссплатформенность
- **PWA** = обычный сайт + `manifest.json`, который Chrome/Edge/Safari разрешают **установить** как приложение (своё окно, иконка в Пуске/Dock, без адресной строки и вкладок). Стора не нужно.
- **Кроссплатформенно:** Windows, macOS, Linux, ChromeOS, Android — одинаково (движок один; различается только «обвязка» ОС: Пуск/таскбар в Windows, Dock/Launchpad на Mac, кнопки окна слева на Mac).
- **iOS/iPadOS — урезано:** установка только через Safari «Добавить на экран»; **Web Push работает только у установленного PWA c iOS 16.4+**; часть железных API недоступна (Serial/USB/HID нет).

## 2. Локальный запуск и установка (важно для теста)
- Установка требует **безопасного контекста**: **HTTPS** ИЛИ **`localhost`/`127.0.0.1`**. **Локальный IP** (`http://192.168.x.x`, `172.x…`) — НЕ безопасный контекст → кнопки «Установить» нет.
- **Тест на десктопе без деплоя:** открывать dev по **`http://localhost:5173`** (не по сетевому IP из вывода Vite `--host`). Ещё ближе к проду — `vite build` + `vite preview` (`localhost:4173`).
- **Тест с телефона по сети:** телефон ходит на комп по IP (не HTTPS) → не поставится. Решение: **тоннель** (`cloudflared tunnel --url http://localhost:5173` или `ngrok http 5173` → временный `https://…`) либо локальный сертификат (`mkcert` + `server.https` в Vite).
- Проверка «установимо ли»: DevTools → **Application → Manifest → Installability** (покажет причину, если нет).

## 3. Привязка к ПРОФИЛЮ Chrome (не к Google-аккаунту)
- **Профиль Chrome** — локальный контейнер (своё хранилище: localStorage/куки/установленные PWA). Существует **всегда**, даже без входа в Google. Вход в Google — лишь опциональная синхронизация поверх.
- PWA ставится **в конкретный профиль** и **всегда работает в его хранилище** (независимо от того, какой профиль открыт в браузере). Отсюда: иконка показывает бейдж профиля; в другом профиле приложения «нет», пока не установить отдельно.
- **Выход из Google-аккаунтов НЕ разлогинивает приложение:** наш JWT лежит в хранилище профиля и остаётся; Google-логина приложение не просит (наша авторизация своя: email/пароль → JWT, в проде SSO Nexus через Supabase — не Google).
- Разлогинит из **нашего** приложения только: удаление профиля Chrome или очистка данных сайта.
- Следствие: на одной машине можно поставить приложение в **разные профили** → в каждом **свой аккаунт** (оператор/мастер одновременно; удобно для теста ролей).

## 4. Детект режима (разный UI/функционал «в приложении» vs «в браузере»)
Две **независимые** оси: (а) ширина экрана (responsive, media-queries) и (б) **режим запуска** (установлено или нет). Комбинируются: «установлено на десктопе» ≠ «телефон в браузере» ≠ «установлено на телефоне».
- **CSS:** `@media (display-mode: standalone) { … }`.
- **JS:** `window.matchMedia('(display-mode: standalone)').matches` (+ событие изменения). Значения: `browser` · `standalone` · `minimal-ui` · `fullscreen` · `window-controls-overlay` · `tabbed`. iOS: `navigator.standalone`.
- ОС/устройство отдельно: `navigator.userAgentData` (desktop/mobile).
- Применение: скрыть свой баннер «Установить» когда уже установлено; в приложении — сразу предлагать уведомления; на десктоп-приложении дать более «рабочий» плотный layout; включить кастом-титлбар только в standalone.

## 5. Кастомизация окна (через manifest.json)
- **Имя/иконка** (`name`, `short_name`, `icons`) — окно, Пуск/Dock.
- **Цвет титлбара** (`theme_color`) — красит верхнюю OS-полосу окна (можно под тему/бренд, в т.ч. по `prefers-color-scheme`).
- **Сплэш при запуске** (`background_color` + иконка).
- **`display`**: `standalone` (наше окно) · `minimal-ui` (+ назад/обновить) · `fullscreen` · `browser`.
- **`window-controls-overlay`** — рисуем **свой контент прямо в титлбаре** (лого, поиск), окно тянется за него → вид почти нативного приложения. Браузерные «три точки/пароли/расширения» в standalone и так не показываются.
- **`shortcuts`** — **джамп-лист**: меню по правому клику на иконке в таскбаре/Dock с быстрыми действиями (диплинки в разделы, напр. «Новая задача», «Мои задачи»).
- **`start_url` / `scope`** — что открывается и какие URL остаются «внутри приложения».
- **`screenshots`** — богатое окно установки.

## 6. Уведомления
- **Web Push** — пуши, **даже когда окно закрыто** (через service worker + подписку; per-app VAPID). У нас эталон — support `docs/NOTIFICATIONS.md`.
- **Badging API** (`navigator.setAppBadge(n)`) — **цифра-бейдж прямо на иконке приложения** в таскбаре/Dock (напр. число новых задач/заявок — видно, не открывая). Снимается `clearAppBadge()`.
- Гибко: разные типы, тихие/важные, действия в уведомлении.

## 7. Устройства и «железо» (веб умеет больше, чем кажется)
- **Камера + микрофон** (`getUserMedia`), **выбор конкретной камеры/аудио** (`enumerateDevices` + `deviceId`), переключение на лету → **видеозвонки/конференции по WebRTC** (P2P аудио/видео/данные, низкая задержка).
- **Захват экрана** (`getDisplayMedia`) — демонстрация/запись экрана или окна.
- **Web Audio** — обработка/визуализация звука.
- **Web Serial / USB / HID / Bluetooth / MIDI** — прямая связь с железом: COM-порты, USB-устройства, сканеры/геймпады, Bluetooth. В экосистеме уже используется (tally, Firmata). Пример: **QR/штрих-сканер** для инвентаризации.
- **Датчики/геолокация** (в основном на мобилке).
- ⚠️ Serial/USB/HID/Bluetooth — **только Chromium-десктоп** (не Safari/Firefox); всё требует HTTPS/localhost и разрешения пользователя.

## 8. Файлы и данные
- **File System Access** — читать/писать файлы на диске с разрешения (экспорт отчётов/логов, «открыть/сохранить как»).
- **Буфер обмена** (`navigator.clipboard`) — копировать/вставлять текст и **картинки**.
- **Share API** (`navigator.share`) — системное «Поделиться».
- **File Handlers** — приложение регистрируется как обработчик типов файлов (открыть `.csv` через наше приложение).

## 9. Офлайн (service worker)
- SW — фоновый скрипт-посредник: **кэширует ассеты/данные** → приложение открывается **без сети** (последние данные из кэша).
- **Background Sync** — действия (отправка сообщения/формы) складываются в **очередь** и уходят на сервер, когда сеть вернётся. Приложение не «умирает» при сетевом провале.

## 10. Deep links (диплинки), протоколы, обработчики
- **Диплинк** — ссылка, которая открывает **установленное приложение сразу на нужном экране/сущности** (не вкладку браузера). Схема: сгенерировали ссылку на конкретный объект (задача/сообщение) → отправили любым каналом (почта/мессенджер) → у кого установлено приложение и есть доступ, клик **проваливается прямо в эту вложенную иерархию** внутри приложения.
  - Пример: ссылка на сообщение в чате `…/app#chat/42/message/1007` → открывается приложение → авто-навигация к этому сообщению (при наличии доступа; проверки прав — на нашей стороне).
  - Технически: URL-роутинг приложения + (опц.) регистрация как обработчика ссылок домена / **protocol handler** (`web+nexus://…`), чтобы система направляла такие ссылки в приложение.
- **Ссылка-как-канал-обмена**: «поделиться сообщением/задачей» = скопировать диплинк и отправить куда угодно; получатель проваливается в контекст.

## 11. Что интересно ЭКОСИСТЕМЕ (приоритеты)
**Nexus (в первую очередь):**
- **Видеосвязь/скриншеринг** в задаче/встрече (getUserMedia/getDisplayMedia/WebRTC + выбор камеры/микрофона) — вероятное ядро видео именно здесь.
- **Badging** — число новых задач/уведомлений на иконке приложения.
- **Кастом-титлбар** (WCO) + shortcuts (джамп-лист) + диплинки в задачи/сообщения.
- **Железо для инвентаризации** (сканеры через Web Serial/USB/HID).
- **Кросс-апп экосистемы:** разные приложения экосистемы устанавливаются **раздельно** и **общаются между собой** (обсуждается отдельно; сюда — как заметка, что механика важна).

**Support (минимально, позже):** в режиме приложения — немного **кастомизировать отображение/UI** (плотнее/иначе, чем на телефоне), скрыть install-баннер, агрессивнее предлагать уведомления; badging с числом новых заявок; видео/скриншеринг клиента для диагностики.

## 12. Быстрые кандидаты на реализацию (low-effort, high-value)
- `useDisplayMode()`-хук + `data-pwa` на корне (рычаг для ветвления UI, ничего не ломает).
- **Badging** с числом новых задач/заявок.
- Скрыть свой баннер «Установить», когда `display-mode: standalone`.
- `shortcuts` в манифесте (джамп-лист в ключевые разделы).
- Позже: WCO-титлбар, офлайн-очередь, видеосвязь, protocol/file handlers.
