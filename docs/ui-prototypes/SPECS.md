# UI Prototypes — Спецификации

Этот файл описывает каждый HTML-прототип: назначение, обязательные механики и концепцию шаблона.
При переносе в React каждая механика из этого файла **обязана быть проверена вручную в браузере**.

---

## 1. Brandbook (`tvshifts-brandbook.html`)

**Назначение:** живой референс дизайн-системы. Не переносится в продакшн как страница — используется как эталон визуала и компонентов при разработке.

**Механики — обязательный чеклист:**
- [ ] Date picker — два режима: «Даты» (мультивыбор конкретных дат) и «Диапазон» (start–end); переключение через тогл
- [ ] Date picker — ввод с клавиатуры в формате `ДД.ММ.ГГГГ`, парсинг 6 и 8 цифр
- [ ] Date picker — календарь не закрывается при выборе дат, только по клику вне области
- [ ] Clock dial — canvas-циферблат 0–24ч, шаг 30 мин (48 слотов)
- [ ] Clock dial — три режима drag: тянуть начало, тянуть конец, тянуть середину дуги (перемещение целиком)
- [ ] Clock dial — в центре отображается длительность выбранного диапазона в реальном времени
- [ ] Clock dial — если start === end, длительность = 24ч (полный круг)
- [ ] Custom select — групповые опции, мультиселект с чекбоксами
- [ ] Темы — переключение dark/light обновляет CSS-переменные без перезагрузки

**Продакшн-компоненты из brandbook:**
- **Переключатель тем** (dark/light) — переносится в хедер AppShell; тема сохраняется в профиле пользователя
- **Date picker** (dates/range режимы) — переносится как переиспользуемый компонент везде где нужен выбор дат
- **Clock dial** — переносится как компонент выбора временного диапазона (планирование смен)
- **Custom select** — переносится как компонент для фильтров и форм

Остальное содержимое brandbook (примеры карточек, типографики, палитра) — визуальный референс, не страница приложения.

## 2. Calendar (`tvshifts-calendar.html`)

**Назначение:** единый корпоративный календарь. Один на всю компанию, но отображает разные наборы событий в зависимости от отдела и видимости календарей.

**Структура данных:**
```js
CALENDARS[]: { id, name, color, checked }
EVENTS[]:    { id, title, date (YYYY-MM-DD), start (HH:MM), end (HH:MM), color, calendar }
```

**Механики — обязательный чеклист:**

*Навигация и виды:*
- [ ] Три вида: Месяц / Неделя / День — переключение через тогл в хедере
- [ ] Навигация вперёд/назад по периоду (кнопки ‹ ›)
- [ ] Кнопка «Сегодня» — возвращает курсор к текущей дате

*Месячный вид:*
- [ ] Клик на ячейку дня → открывается боковая панель с событиями дня
- [ ] События отображаются как цветные пилюли; если событий > 3 — показать «+N ещё»
- [ ] Клик на пилюлю события → открыть модал редактирования (не открывать панель)
- [ ] Выбранный день подсвечен; сегодня — акцентной рамкой

*Недельный и дневной вид:*
- [ ] Вертикальная шкала времени, 1px = 1 минута
- [ ] Рабочее время 10:00–18:30 выделено фоном `rgba(255,255,255,0.025)`, линии часов ярче
- [ ] Красная линия текущего времени (только сегодня)
- [ ] Drag-to-create: зажать пустую область → тянуть → ghost-элемент с превью времени → отпустить → открыть модал с pre-fill датой и временем, snap 15 мин
- [ ] Клик на блок события → открыть модал редактирования, `e.stopPropagation()` чтобы не триггерить drag

*Overlap layout (алгоритм — нельзя упрощать):*
- [ ] Параллельные события делят ширину колонки поровну
- [ ] Алгоритм: кластеризация → жадное назначение sub-col внутри кластера
- [ ] `total` для всего кластера, а не для каждой пары — иначе события "прыгают" в соседнюю колонку

*Модал создания/редактирования:*
- [ ] Один и тот же модал для create и edit (переключение через `editingEventId`)
- [ ] Edit mode: заголовок «Редактировать», кнопка «Сохранить», кнопка «Удалить» видима
- [ ] Create mode: заголовок «Новое событие», кнопка «Создать», «Удалить» скрыта
- [ ] Выбор календаря из списка (цветные радио-кнопки)
- [ ] Закрытие по клику на backdrop

*Левый сайдбар:*
- [ ] 6 (и более) календарей с чекбоксами и цветными иконками
- [ ] Toggle видимости = скрыть/показать события этого календаря во всех видах

**Концепция шаблона:**
```
<CalendarPage calendars={deptCalendars} filterFn={byDept} />
```
| Параметр | Что меняется |
|----------|--------------|
| `calendars[]` | набор и цвета календарей для конкретного отдела |
| `filterFn` | правило фильтрации событий из общей БД |
| Названия календарей | «Эфиры», «Монтаж», «Личное» и т.д. под каждый отдел |

Базовая механика (drag, overlap, modal) — не меняется.

## 3. Kanban (`tvshifts-kanban.html`)

**Назначение:** доска задач с drag-and-drop между колонками. Базовый шаблон — три колонки по статусу, но конфигурируется под любую логику группировки.

**Структура данных:**
```js
COLS[]:  { id, label, color }
CARDS[]: { id, col, title, tag, tagColor, assignee, priority ('high'|'medium'|'low'), done }
```

**Механики — обязательный чеклист:**
- [ ] Drag card между колонками (HTML5 drag API: dragstart, dragover, drop)
- [ ] Карточка визуально «поднимается» при drag (opacity/scale)
- [ ] Drop — карточка перемещается в целевую колонку, список перерисовывается
- [ ] Toggle done — зачёркивание заголовка, изменение иконки
- [ ] Добавить карточку в колонку — кнопка «+», prompt с названием
- [ ] Приоритеты: high `#E8194B`, medium `#F59E0B`, low `#464658`
- [ ] Доска центрирована горизонтально, колонки одинаковой ширины

**Концепция шаблона:**
```
<KanbanBoard columns={colConfig} groupBy="status|assignee|type" />
```
| Параметр | Примеры значений |
|----------|-----------------|
| `columns[]` | [Бэклог, В работе, Готово] или [Продюсер А, Продюсер Б, Продюсер В] |
| `groupBy` | `'status'` — по статусу задачи; `'assignee'` — кто выполняет |
| Количество колонок | 2–5, динамически |

## 4. Gantt (`tvshifts-gantt.html`)

**Назначение:** временная шкала задач с визуализацией длительности и дедлайнов.

**Структура данных:**
```js
TASKS[]: { id, title, start (YYYY-MM-DD), end, color, done }
// Grouped mode (будущее):
GROUPS[]: { id, title, start, end, tasks[] }
```

**Константы:**
```js
DAY_W = 40px     // ширина одного дня
ROW_H = 48px     // высота строки
TOTAL_DAYS = 30  // количество отображаемых дней
```

**Механики — обязательный чеклист:**
- [ ] Горизонтальная шкала дат в хедере; выходные выделены другим цветом
- [ ] Бар задачи: позиция и ширина из start/end дат, пиксель точный
- [ ] Drag бара целиком — перемещает start и end с сохранением длительности
- [ ] Resize левого края — меняет start, end фиксирован
- [ ] Resize правого края — меняет end, start фиксирован
- [ ] Drag/resize обновляет даты в реальном времени (лейбл над баром)
- [ ] Создание новой задачи: drag по пустой строке → ghost outline → отпустить → добавить в список
- [ ] Tooltip при hover на бар (название, даты, длительность)
- [ ] Toggle done — бар тускнеет

**Концепция шаблона:**

| Mode | Описание |
|------|----------|
| `flat` | задачи с индивидуальными дедлайнами (текущий прототип) |
| `grouped` | группа задач → строка-заголовок с суммарным диапазоном → вложенные строки подзадач |

```
<GanttChart mode="flat|grouped" tasks={tasks} groups={groups} startDate={...} totalDays={30} />
```

## 5. Node Canvas (`tvshifts-node-canvas.html`)

**Назначение:** карта проекта — визуализация связей Project → WorkItem → Department → Person. Появляется после Phase 5–6.

**Структура данных:**
```js
NODES[]: { id, type ('project'|'wi'|'dept'|'person'), x, y, title, sub, chips[], detail, color, initials, icon, iconBg }
EDGES[]: { from, to, color }
```

**Механики — обязательный чеклист:**
- [ ] Pan: drag по пустому холсту — сдвигает всё поле
- [ ] Zoom: колёсико мыши или кнопки +/− (диапазон разумный, без бесконечного зума)
- [ ] Reset view / Fit all — кнопки сброса к исходному виду
- [ ] Drag нод: перетащить узел → обновить позицию + перерисовать рёбра
- [ ] Нода при drag — лёгкий scale(1.02) для обратной связи
- [ ] Клик на ноду → открыть боковую панель с деталями
- [ ] Minimap — уменьшенный preview всего холста в правом нижнем углу, обновляется в реальном времени
- [ ] Рёбра — кривые (quadratic bezier), цвет наследует от ноды-источника

**Концепция шаблона:**
Данные полностью из API. Структура нод и рёбер фиксирована (тип нод = тип сущности). Конфигурировать не нужно — только подключить реальные данные.

```
<NodeCanvas nodes={apiNodes} edges={apiEdges} />
```
