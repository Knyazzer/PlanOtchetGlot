## Расхождения с каноном — НЕ переносить в код

### 1. Механики задач — макет по старому брифу (до вердиктов исследования)
`mockData.ts` / `Tasks.tsx` содержат **отменённые** механики:
- `dateFrom/dateTo` (диапазон дат) — **отменено В-1**: у нас одна дата (`startDate`) + опц. `deadline`; гант макета рисует бары по диапазону — наш рисует по дате→дедлайну
- `priority` (Высокий/Средний/Низкий) — **отменено В-5** (0 использований в проде)
- `participants` (соисполнители) — **отменено В-4**
- `comments`-счётчик на карточке — отменено (обсуждение через чат-карточки)
- На доске **нет** нашей группировки «По статусу · По клиенту · Мои колонки» (ключевой инсайт данных) — только статусные колонки

→ Из Tasks макета берём **скелеты** Таблицы/Ганта/Календаря (вёрстка, плотность), наполнение — по канону.

### 2. Карточка проекта (`Projects.tsx`) — неверна, канон в Nexus
Макет близок по духу (Client → Project → WorkItem, три роли продюсеров, бюджет-бар), но:

| Макет | Канон Nexus (`schema.prisma`) |
|---|---|
| статусы проекта: В работе/Завершён/Планирование/Приостановлен | enum `draft / active / done / cancelled` |
| у WorkItem нет статуса | enum `request / active / done / rejected / cancelled` — основа Workflow-вкладки |
| `expenses: число` | `Expense[]` — статьи расходов с категориями (`equipment/transport/fees/postproduction/other`), автором, датой |
| `division: строка` | `WorkItemDivision` — many-to-many подключение отделов |
| **нет Track-слоя** | `Track.workItemId` — треки с задачами и прогрессом внутри WI |
| нет brief/kpLink | `Project.brief`, `Project.kpLink` |

→ Берём из макета **витрину**: группировка по клиентам, раскрывающиеся карточки, бюджет-бар с порогами (>70% жёлтый, >90% красный), строка ролей продюсеров. Содержимое — строго канон.

### 3. Мелочи
- «Гига-смена» в легенде Свода — у нас не сидируется (0 использований, В-6)
- Вес «выходной» = 0 в моках — у нас `null` (не суммируется)
- Calendar: только месяц/неделя, без drag-to-create — **наш CalendarPage уже богаче**, берём только цветовую подачу
- Chats упрощённый — наш WS-модуль полнее, берём только скин списка/пузырей

## Что внедряем (порядок)

1. **Токены тем** из `theme.css` → `kit.css` Nexus: light/dark наборы + `--sidebar-*` (заменят хардкод-константы SB в AppShell) + `--chart-1..5`. Решён Q-UI-1: **Inter** (+ JetBrains Mono для чисел).
2. **Settings-скелет** (6 вкладок) — носитель для предстоящих «Роли и доступы» и «Форматы дня» (остаток 1.8).
3. **Notifications-панель** — эталон для Этапа 3 (уведомления).
4. **Team** — эталон новой страницы «Команда».
5. **Cabinet** — эталон личного кабинета (неделя + задачи + мой день).
6. Рестайл существующих страниц (Свод/Аналитика/Задачи) — по плотности и подаче макета, наполнение не менять.
