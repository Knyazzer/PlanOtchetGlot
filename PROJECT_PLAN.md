# TV Shifts — Приложение управления сменами ТВ-команды

## 1. Суть проекта

Веб-приложение для ТВ-департамента. Заменяет ручное ведение Google Sheets: автоматически забирает данные о проектах и командах, формирует производственный календарь, ведёт учёт смен и переработок, содержит бэклог задач.

---

## 2. Участники и роли

| Роль | Доступ |
|------|--------|
| **Сотрудник** | Видит свой календарь, смены, лог изменений, берёт задачи из бэклога |
| **Администратор ТВ-департамента** | Полный контроль: подтверждение смен, редактирование, просмотр всех логов, управление мероприятиями |
| **Продюсер** | Чтение: производственный календарь, загруженность команды, кнопка «Обновить данные» |

Команда: видеоинженер, звукорежиссёр, оператор, режиссёр (и другие специалисты из матриц).

---

## 3. Источники данных (Google Sheets, только чтение)

### 3.1 Таблица проектов
Заполняется продюсерами. Содержит:
- Название клиента
- Название мероприятия
- Дата (может быть конкретной, примерной или просто месяц)
- Исполнительный продюсер, линейный продюсер, аккаунт-менеджер
- **Статус через цвет ячейки**: подсвеченная ячейка = это поле ещё не точное
- **Планируется добавить**: столбец с ID матрицы из реестра

### 3.2 Реестр матриц
Содержит:
- ID матрицы (уникальный)
- Ссылка на матрицу (отдельная Google Sheets)
- Тип проекта (ТВ, видеопроизводство, радио и т.д.)
- Ответственный продюсер
- Даты и описание

### 3.3 Матрица проекта (отдельный документ на каждый проект)
Содержит:
- Список специалистов (полное ФИО, выбирается из базы сотрудников)
- Их смены и даты выходов
- Стоимость услуг
- Сводный лист: расходы / доходы / профит

**Важно**: матрицы читаются через Google Sheets API v4.
- Цвет ячеек — читается (`userEnteredFormat.backgroundColor`)
- Объединённые ячейки — читается (массив `merges` в ответе API)

## 4. Логика смен

### Формула минимума смен (на месяц)
```
min_shifts = ceil(рабочих_дней_в_месяце × 16 / 22)
```
Считается одинаково для всей команды. Пересчитывается каждый месяц.

| Ситуация | Действие |
|----------|----------|
| Смен > минимума | Переработка (считается автоматически) |
| Смен < минимума | Администратор добавляет отпуск вручную |

### Подтверждение смены
- В идеальном сценарии: сотрудник **ничего не заполняет** — смены берутся из матриц автоматически
- Администратор/руководитель **подтверждает** смены или редактирует их
- Редактирование задним числом — только администратор

### Типы смен
Застройка, эфир, сбор оборудования, демонтаж и др.

## 5. Производственный календарь

### Отображение
- Навигация **по неделям** (вперёд/назад)
- Каждый день показывает проекты и занятых сотрудников
- Правая панель: **список неподтверждённых проектов** (нет точной даты — только месяц или вообще без даты)

### Статусы проекта
| Статус | Источник | Описание |
|--------|----------|----------|
| **Предварительно** | Projects table | Есть подсвеченные ячейки (что-то не точно) |
| **К реализации** | Projects table | Все поля утверждены |
| **Завершён** | Projects table / вручную | Проект прошёл |
| **Ручной** | Наша система | Создан внутри приложения администратором |

### Конфликты
- Один сотрудник в двух проектах в один день → **подсвечивается**, с возможностью переназначить
- Имя в матрице не найдено в системе → **уведомление в колокольчике**

## 6. Синхронизация с Google Sheets

### Расписание
- Автоматически: раз в **30 минут**
- Вручную: кнопка «Обновить данные» (доступна администратору и продюсеру)

### Порядок синхронизации
1. Читаем таблицу проектов → обновляем список проектов
2. Читаем реестр матриц → получаем список ссылок
3. Для каждой матрицы — читаем специалистов и даты
4. Маппим специалистов на аккаунты по полному ФИО
5. Обновляем производственный календарь

### Конфликт данных (merge UI)
Если синхронизированные данные расходятся с ручными записями:
- Показываем **diff-панель**: наш вариант слева, пришедший справа
- Кнопки: **«Принять наше»** / **«Принять их»**
- При следующей синхронизации — снова проверяем расхождения

### Уведомления (колокольчик, правый верхний угол)
- Проект есть в таблице проектов, но матрицы нет
- Имя в матрице не найдено среди аккаунтов системы
- Конфликты после синхронизации
- Лог последних изменений

---

## 7. Лог изменений

- **В аккаунте сотрудника**: его смены изменились (переезд на другой проект, смена даты, и т.д.)
- **В admin-панели**: все изменения по всем сущностям с автором действия

---

## 8. Task Tracker (Бэклог)

- Общий список задач (не привязан к конкретному проекту)
- Сотрудник открывает бэклог → берёт задачу → статус меняется на «В работе»
- Статусы: **Открыта / В работе / Выполнена**
- Администратор видит: кто, что, когда взял и выполнил
- **В будущем**: администратор начисляет бонусные баллы за выполненные задачи

## 9. Технический стек

### Монорепо (pnpm workspaces)
```
/apps
  /web    — React-приложение
  /api    — Fastify-сервер
/packages
  /db     — Prisma schema + migrations
```

### Frontend (`/apps/web`)
| Инструмент | Назначение |
|-----------|-----------|
| React + TypeScript + Vite | Базовый стек |
| FullCalendar | Производственный календарь (неделя/месяц) |
| shadcn/ui | UI-компоненты (таблицы, формы, модалки, тосты) |
| TanStack Query | Кэширование запросов, синхронизация состояния |
| TanStack Router | Роутинг |

### Backend (`/apps/api`)
| Инструмент | Назначение |
|-----------|-----------|
| Node.js + TypeScript + Fastify | HTTP-сервер |
| Prisma ORM | Работа с базой данных |
| googleapis (npm) | Google Sheets API v4 (read-only) |
| node-cron | Планировщик синхронизации (каждые 30 мин) |
| JWT + bcrypt | Авторизация |

### База данных
**PostgreSQL** — выбрана из-за: аналитических запросов, фильтрации, конкурентного доступа, роста данных. Работает локально в Docker, без изменений переезжает на сервер.

### Инфраструктура
**Docker + Docker Compose** — один файл поднимает всё окружение (Postgres + API + Web). Одинаково работает в локальной сети и на удалённом сервере.

## 10. Основные экраны

1. **Производственный календарь** — главный экран, недельный вид, конфликты, боковая панель неподтверждённых
2. **Детальная карточка проекта** — все участники, смены, даты, статус, источник данных
3. **Профиль сотрудника** — его смены за месяц, баллы, лог изменений
4. **Admin-панель** — управление сотрудниками, подтверждение смен, маппинг ФИО, настройки
5. **Синхронизация** — статус последней синхронизации, diff-UI, колокольчик
6. **Бэклог задач** — список задач, статусы, кто взял

## 12. Этапы реализации

### Этап 1 — Фундамент (локальная сеть)
- Docker Compose окружение
- PostgreSQL + Prisma schema
- Авторизация (JWT, роли)
- Admin-панель: управление сотрудниками и проектами вручную

### Этап 2 — Google Sheets интеграция
- Подключение Google Sheets API
- Парсер таблицы проектов (с цветами)
- Парсер реестра матриц
- Парсер индивидуальных матриц
- Маппинг ФИО → аккаунты
- Планировщик синхронизации

### Этап 3 — Производственный календарь
- Недельный вид
- Конфликты сотрудников
- Боковая панель неподтверждённых
- Diff-UI для конфликтов данных
- Колокольчик уведомлений

### Этап 4 — Учёт смен
- Автозаполнение из матриц
- Подтверждение администратором
- Подсчёт по формуле
- Лог изменений (для сотрудника и admin)

### Этап 5 — Бэклог и аналитика
- Task Tracker
- Дашборды: кто сколько отработал, по проектам, фильтры

### Этап 6 — Деплой на сервер
- Перенос Docker Compose на VPS
- Настройка домена и HTTPS
