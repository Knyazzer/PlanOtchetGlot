# Планировщик смены — Design Spec

> Референс-мокап: `shift-planner-v6.html`

---

## Концепция

Вкладка «Планировщик смены» внутри детальной карточки матрицы (внутренней). Горизонтальная timeline-доска: каждый человек — одна строка, все его блоки видны в ней одновременно. Тонкая линия-коннектор соединяет блоки одного человека через весь таймлайн, визуально показывая полную занятость.

---

## Место в UI

Вкладка между «Команда» и «Производственные расходы» в `InternalShiftsPanel.tsx`.

---

## Блоки (Block)

Блоки = группы команды из вкладки «Команда» (Сбор, Завоз, Монтаж, Эфир, Демонтаж, Вывоз и их копии).

Каждый блок имеет:
- `id` — уникальный (efir, efir_2, efir_3, demontazh_2 и т.д.)
- `label` — название (Эфир, Демонтаж…)
- `color` — цвет группы
- `date` — дата блока (может отличаться от даты проекта; Сбор/Завоз = день до, Демонтаж = ночь после)
- `timeFrom` / `timeTo` — временной диапазон внутри дня

Хранятся в `group_schedule` JSONB на `status_rows`.

### Несколько копий одного типа блока

Эфир → Эфир_2 → Эфир_3 (разные дни или разные временные слоты). Каждая копия — отдельный блок с собственной датой и диапазоном. Та же логика для Демонтажа.

---

## Таймлайн

### Временная ось

- Абсолютное время в минутах от полуночи опорного дня (дата проекта = день 0).
- День −1 = день до, день +1 = следующий день и т.д.
- Шаг отображения: 30 минут.

### Динамический диапазон

Таймлайн автоматически расширяется/сжимается по крайним блокам:
- `rangeStart = min(block.absFrom) − 60 мин`
- `rangeEnd   = max(block.absTo)   + 60 мин`
- Округление до 30 минут.

При перемещении блока за текущие края — таймлайн расширяется на release.

### Шапка (header)

Три слоя сверху вниз:
1. **Строка дат** — дата для каждого видимого дня, границы дней — вертикальная линия
2. **Блоки** — цветные бары с названием, временем и датой. При перекрытии двух блоков по времени — стекинг на разные строки (greedy interval assignment)
3. **Тики времени** — каждые 30 мин; часовые метки подписаны

---

## Строки (person-first layout)

Одна строка на одного специалиста. Специалисты сгруппированы по бригадам (секции с цветовым маркером).

### Внутри строки

- **Тонкая горизонтальная линия** — от первого до последнего бара, цвет `#1e3a5f`
- **Точки** на стыках баров с линией (начало и конец каждого бара)
- **Цветные бары** для каждого блока, в котором участвует человек. Цвет = цвет блока.
- Внутри бара: `timeFrom` слева, название блока по центру, `timeTo` справа (font-size 9px)

### Нахлёст баров

Если два блока человека перекрываются по времени (например, Эфир и Демонтаж идут одновременно) — greedy track assignment внутри строки. Строка автоматически увеличивается по высоте (на каждый дополнительный трек +26px).

### Высота строки

- 1 трек → 40px
- N треков → max(40, N × 26 + 10)px

## Взаимодействие

### Перемещение блока (шапка)

- Клик + drag по центральной зоне бара в шапке → блок двигается целиком
- Все бары участников этого блока смещаются вместе (proportional shift)
- DOM обновляется напрямую во время drag (`style.left`, `style.width`); `render()` только при release
- Тултип показывает `дата  HH:MM – HH:MM` во время перетаскивания

### Изменение границ блока (resize)

- Вертикальные ручки по краям бара блока в шапке (ширина 14px, cursor `ew-resize`)
- При resize бара блока — бары участников автоматически зажимаются в новые границы блока (на release)

### Изменение диапазона участника

- Ручки на левом и правом крае каждого бара участника в треках
- Ограничены диапазоном родительского блока
- Шаг: 30 минут

### Двойной клик по имени

Все бары этого человека растягиваются на полный диапазон своих блоков.

### Попап даты блока

Клик без перемещения (< 5px) по блоку в шапке → попап с:
- Названием блока
- Кнопками ◄ / ► для смены дня (шаг ±1440 минут)
- Текущим временным диапазоном
- Кнопкой «Закрыть»

При смене даты — все бары участников блока сдвигаются на тот же шаг.

### Зум

- Кнопки +/− в topbar: шаг ×1.3 / ÷1.3, диапазон 18%–600%
- Ctrl+колесо мыши с привязкой к позиции курсора
- При зуме сохраняется позиция центра видимой области

## Scroll

Единственный скролл-контейнер — `tracksScroll` (горизонтальный + вертикальный).  
`headerScroll` и `namesScroll` синхронизируются через JS (`scroll` event listener), без собственных полос прокрутки.

CSS grid: 2×2 (corner | header | names | tracks). Header row height — динамическая (зависит от числа block tracks).

---

## Хранение данных

### Блоки

Читаются из `group_schedule` JSONB (`status_rows`). Структура ключей:
```
efir       → { date, timeFrom, timeTo, ... }
efir_2     → { date, timeFrom, timeTo, ... }
demontazh  → { date, timeFrom, timeTo, ... }
demontazh_2 → { date, timeFrom, timeTo, ... }
```

### Участники блоков

Читаются из `project_members` через `group_name`. Персональные диапазоны хранятся отдельным полем (например, `field_approvals` или новый JSONB `shift_schedule` на `project_members`).

> ⚠️ Точная схема хранения персональных диапазонов требует отдельного решения при реализации (текущий `field_approvals` JSONB может быть перегружен другой логикой).
