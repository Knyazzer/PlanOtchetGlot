# Формат JSON для калькулятора баллов

Этот документ описывает структуру файла, который экспортирует и импортирует калькулятор `Калькулятор баллов.html`. Нужен для автоматической генерации месячных снимков скриптом или LLM-агентом.

Файл представляет собой один JSON-объект верхнего уровня с семью обязательными секциями. При импорте приложение полностью заменяет текущее состояние на содержимое файла.

## Минимальные требования

Для прохождения импортной валидации файл ДОЛЖЕН содержать непустые поля `ownProjects`, `tvTeam`, `techTeam`. Остальные поля желательны, недостающие заполнятся дефолтами через механизм миграции.

## Верхнеуровневая структура

```json
{
  "workdays": 21,
  "coefs": { ... },
  "ownProjects": [ ... ],
  "extProjects": [ ... ],
  "tvTeam": [ ... ],
  "techTeam": [ ... ],
  "participation": { ... },
  "nonProj": { ... },
  "activeDept": "tv",
  "nextOwnId": 3,
  "nextExtId": 102
}
```

### Поля

| Поле | Тип | Описание |
|---|---|---|
| `workdays` | number | Количество рабочих дней в месяце. Используется для расчёта порога. Диапазон 15–23. |
| `coefs` | object | Все настраиваемые коэффициенты. См. ниже. |
| `ownProjects` | array | Свои проекты с грейдами. |
| `extProjects` | array | Внешние проекты без грейдов. |
| `tvTeam` | array | Состав ТВ-команды. |
| `techTeam` | array | Состав тех-департамента. |
| `participation` | object | Матрица участия: кто в каком проекте на каких сменах. |
| `nonProj` | object | Внепроектная работа в днях. |
| `activeDept` | string | Какой отдел был открыт в сводке (`"tv"` или `"tech"`). Не влияет на расчёт. |
| `nextOwnId` | number | Счётчик id для новых своих проектов. Должен быть больше всех id в `ownProjects`. |
| `nextExtId` | number | Счётчик id для новых внешних проектов. Должен быть больше всех id в `extProjects`. |

## Секция coefs

Все коэффициенты системы. Если опустить — применятся дефолтные значения.

```json
"coefs": {
  "thresholdMult": 0.76,
  "grades": {
    "S": 0.7,
    "M": 1.0,
    "L": 1.5,
    "XL": 2.5
  },
  "tv": {
    "shifts": {
      "bld": 1.0,
      "air": 1.0,
      "dem": 1.0,
      "shoot": 1.0,
      "gather": 0.7,
      "trans": 1.0
    },
    "nonproj": {
      "office": 0.7,
      "sound": 0.7,
      "sort": 0.5
    }
  },
  "tech": {
    "shifts": { ... },
    "nonproj": { ... }
  }
}
```

**Дефолтные значения:**

- `thresholdMult`: 0.76 (= 16 / 21)
- `grades`: S=0.7, M=1.0, L=1.5, XL=2.5
- `shifts` (одинаково для tv и tech по умолчанию):
  - `bld` (застройка) = 1.0
  - `air` (эфир) = 1.0
  - `dem` (демонтаж) = 1.0
  - `shoot` (съёмка) = 1.0
  - `gather` (сбор оборудования) = 0.7
  - `trans` (транспортировка) = 1.0
- `nonproj`:
  - `office` (работа в офисе) = 0.7
  - `sound` (саунд-дизайн) = 0.7
  - `sort` (сортировка склада) = 0.5

## Секция ownProjects

Массив своих проектов, каждый со своими грейдами для ТВ и тех.

```json
"ownProjects": [
  {
    "id": 1,
    "name": "Подкаст",
    "tvGrade": "S",
    "techGrade": "M"
  },
  {
    "id": 2,
    "name": "Конференция",
    "tvGrade": "L",
    "techGrade": "XL"
  }
]
```

### Поля проекта

| Поле | Тип | Описание |
|---|---|---|
| `id` | number | Уникальный числовой идентификатор. Должен быть уникален внутри `ownProjects` и между `ownProjects` и `extProjects`. |
| `name` | string | Название проекта. |
| `tvGrade` | string | Грейд для ТВ-команды: `"S"`, `"M"`, `"L"`, `"XL"`. |
| `techGrade` | string | Грейд для тех-департамента: `"S"`, `"M"`, `"L"`, `"XL"`. |

**Рекомендация по id:** свои проекты обычно нумеруются с 1. `nextOwnId` должен быть на 1 больше максимального.

## Секция extProjects

Массив внешних проектов (для других отделов, клиентов). Без грейдов.

```json
"extProjects": [
  {
    "id": 101,
    "name": "Студия для SMM"
  }
]
```

**Рекомендация по id:** внешние проекты обычно нумеруются с 101, чтобы визуально отличаться от своих. `nextExtId` на 1 больше максимального.

## Секции tvTeam и techTeam

Массивы сотрудников с ролями.

```json
"tvTeam": [
  { "name": "Режиссёр 1",      "role": "Режиссёр" },
  { "name": "Звукорежиссёр 1", "role": "Звукорежиссёр" },
  { "name": "Видеоинженер 1",  "role": "Видеоинженер" },
  { "name": "Оператор 1",      "role": "Оператор" }
],
"techTeam": [
  { "name": "Руководитель", "role": "Рук. тех" },
  { "name": "Инженер 1",    "role": "Инженер" },
  { "name": "Инженер 2",    "role": "Инженер" }
]
```

### Допустимые роли

**Только для tvTeam:**
- `"Режиссёр"`
- `"Звукорежиссёр"`
- `"Видеоинженер"`
- `"Оператор"`

**Только для techTeam:**
- `"Рук. тех"`
- `"Инженер"`

Значения ролей чувствительны к регистру и должны совпадать буква в букву. Использование роли, которой нет в списке, сломает расчёт — для такого сотрудника не будет известна структура смен.

### Какие смены доступны каждой роли

| Роль | Смены в проектах | Внепроектная работа |
|---|---|---|
| Режиссёр | bld, air, dem | office |
| Звукорежиссёр | bld, air, dem | office, sound |
| Видеоинженер | bld, air, dem | office |
| Оператор | bld, air, shoot, dem | office |
| Рук. тех | bld, air, gather, trans, dem | office, sort |
| Инженер | bld, air, gather, trans, dem | sort |

Если в `participation` или `nonProj` прописать смену/активность, недоступную данной роли, она будет проигнорирована при расчёте.

## Секция participation

Матрица участия. Три вложенных уровня: отдел → индекс сотрудника → id проекта → ключ смены → true/false.

```json
"participation": {
  "tv": {
    "0": {
      "1": {
        "bld": true,
        "air": true,
        "dem": true
      },
      "2": {
        "bld": true,
        "air": true,
        "dem": true
      }
    },
    "3": {
      "1": {
        "bld": true,
        "air": true,
        "shoot": true,
        "dem": true
      },
      "101": {
        "shoot": true
      }
    }
  },
  "tech": {
    "0": {
      "1": { "bld": true, "air": true, "gather": true, "trans": true, "dem": true }
    }
  }
}
```

### Правила

- Первый ключ: `"tv"` или `"tech"`.
- Второй ключ (индекс сотрудника) — строка с числом, соответствует позиции в `tvTeam` или `techTeam` начиная с 0. Например, `"0"` в `tv` = первый элемент `tvTeam`.
- Третий ключ (id проекта) — строка с числом, совпадает с `id` из `ownProjects` или `extProjects`.
- Четвёртый ключ — ключ смены: `bld`, `air`, `dem`, `shoot`, `gather`, `trans`.
- Значение: `true` если сотрудник был на этой смене в этом проекте, `false` или отсутствует — не был.

**Отсутствующий ключ равен false.** Можно опускать всё, что не нужно, чтобы файл был компактнее.

### Пример: оператор (индекс 3 в tvTeam) участвует во всех сменах проекта id=2 и в съёмке внешнего проекта 101

```json
"tv": {
  "3": {
    "2": { "bld": true, "air": true, "shoot": true, "dem": true },
    "101": { "shoot": true }
  }
}
```

## Секция nonProj

Внепроектная работа. Два уровня: отдел → индекс сотрудника → ключ активности → число дней.

```json
"nonProj": {
  "tv": {
    "0": { "office": 2 },
    "1": { "office": 2, "sound": 5 },
    "2": { "office": 2 },
    "3": { "office": 1 }
  },
  "tech": {
    "0": { "office": 3, "sort": 3 },
    "1": { "sort": 4 },
    "2": { "sort": 4 }
  }
}
```

### Правила

- Ключ активности: `office`, `sound`, `sort`.
- Значение — неотрицательное целое число (дней в месяце).
- Можно опускать нули и активности, которые не применимы роли.

## Чек-лист генерации нового месяца

При автоматической генерации JSON под новый месяц:

1. **workdays** — поставить реальное число рабочих дней месяца.
2. **coefs** — оставить дефолтными (или скопировать из эталонного файла с откалиброванными коэффициентами).
3. **tvTeam, techTeam** — скопировать из предыдущего месяца, не менять без явного запроса.
4. **ownProjects** — заполнить список месяца. id начинать с 1, считать `nextOwnId` как `max(id) + 1`.
5. **extProjects** — заполнить список внешних проектов. id начинать с 101, считать `nextExtId` как `max(id) + 1`.
6. **participation** — для каждого сотрудника каждого отдела проставить участие в проектах. По умолчанию "все проектные смены сотрудника включены во всех своих проектах, участие во внешних проектах — только там, где было реально".
7. **nonProj** — поставить число дней внепроектной работы по каждому сотруднику. 0 или отсутствие — нет такой работы.
8. **activeDept** = `"tv"` по умолчанию.

## Типичные ошибки

**Ошибка: "Неверный формат файла" при импорте.** Отсутствует одно из обязательных полей: `ownProjects`, `tvTeam`, `techTeam`. Убедись, что все три присутствуют как массивы (пусть даже пустые, хотя пустой `tvTeam`/`techTeam` не имеет смысла).

**Расчёт показывает 0 баллов у сотрудника, хотя в `participation` он отмечен.** Частые причины:
- Роль написана с опечаткой (`"Режисер"` вместо `"Режиссёр"`). Регистр и знаки важны.
- В `participation` проставлена смена, которой у этой роли нет (например, `shoot` у режиссёра).
- Id проекта в `participation` не совпадает с `id` в `ownProjects`/`extProjects`.
- Индекс сотрудника в `participation` указан не как строка (`0` вместо `"0"`). JSON-ключи всегда строки.

**Проект показывается во внешних вместо своих (или наоборот).** Определяется не грейдом, а тем, в каком массиве лежит: `ownProjects` или `extProjects`. Один и тот же id в обоих массивах не допускается.

**Коэффициент не применился.** Проверь путь в `coefs`: например, коэффициент офиса для ТВ лежит в `coefs.tv.nonproj.office`, а не в `coefs.nonproj.office`.
