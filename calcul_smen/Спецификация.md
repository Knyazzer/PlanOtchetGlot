# Калькулятор баллов ТВ и тех-команды — описание

Инструмент для расчёта баллов загрузки сотрудников ТВ-команды и тех-департамента. Помогает видеть, кто в месяце переработал, а кто не добрал до порога, с учётом участия в проектах разной сложности и внепроектной работы.

Работает в браузере без сервера: открываешь `Калькулятор баллов.html` двойным кликом, файл поднимается локально, данные хранятся в `localStorage` браузера.

## Зачем

Раньше у компании была непрозрачная система премирования: оклад + произвольная квартальная сумма без привязки к фактической нагрузке. Этот калькулятор — инструмент моделирования новой системы, в которой:

- Баллы существуют только для расчёта доплат за переработки, не для штрафов
- Оклад защищён, не режется при недоборе
- Разные проекты имеют разный вес в зависимости от сложности
- Внешние проекты (для других отделов, клиентов) учитываются отдельно от своих
- Внепроектная работа (офис, саунд-дизайн, склад) тоже даёт баллы
- ТВ и тех-команда имеют независимые коэффициенты смен — одна и та же работа может весить по-разному для разных отделов

## Как устроена математика

### Баллы за смену

Одна смена сотрудника даёт баллы по формуле:

```
баллы_за_смену = базовый_коэффициент_смены × множитель_грейда_проекта
```

**Базовый коэффициент** — это "себестоимость" типа смены. Настраивается отдельно для ТВ и тех. По умолчанию застройка/эфир/демонтаж/съёмка/транспортировка идут по 1.0, сбор оборудования — 0.7.

**Множитель грейда** применяется только для своих проектов. По умолчанию:
- S (простой) — 0.7
- M (стандартный) — 1.0
- L (сложный) — 1.5
- XL (экстремальный) — 2.5

### Три типа работы

**1. Смены в своих проектах.** Проекты внутри департамента со своим грейдом. Умножаются на множитель грейда:
```
базовый × грейд проекта
```
Пример: ТВ-режиссёр на эфире L-проекта → 1.0 × 1.5 = 1.5 балла.

**2. Смены во внешних проектах.** Работа для других отделов или клиентов — грейд не ставится, считается по базовой себестоимости без умножения:
```
базовый (без множителя)
```
Пример: оператор снимает для SMM → 1.0 балла за смену съёмки независимо от сложности.

**3. Внепроектная работа.** Офис, саунд-дизайн, сортировка склада. Для каждого сотрудника задаётся число дней в месяц. Коэффициенты настраиваются отдельно для ТВ и тех:
```
коэффициент × число дней
```
По умолчанию офис/саунд — 0.7, сортировка склада — 0.5.

### Порог переработки

Рассчитывается от количества рабочих дней в месяце:
```
порог = рабочие_дни × множитель_порога
```
Множитель по умолчанию 0.76 — это 16 смен на 21 рабочий день, зашитое ранее соотношение компании.

- Набрал меньше порога — ничего не происходит, получаешь оклад в полном объёме.
- Набрал больше порога — превышение идёт в доплаты за переработку по ступенчатой шкале (сам механизм расчёта рублей из баллов живёт вне этого калькулятора).

## Типы смен по ролям

Структура смен зашита в коде и не меняется через UI (только коэффициенты). Для каждой роли свой набор.

**ТВ-команда:**
- Режиссёр — застройка, эфир, демонтаж
- Звукорежиссёр — застройка, эфир, демонтаж (+ саунд-дизайн как внепроектная работа)
- Видеоинженер — застройка, эфир, демонтаж
- Оператор — застройка, эфир, съёмка, демонтаж

**Тех-департамент:**
- Рук. тех — застройка, эфир, сбор оборудования, транспортировка, демонтаж (+ офис и сортировка склада)
- Инженер — застройка, эфир, сбор оборудования, транспортировка, демонтаж (+ сортировка склада)

Все смены могут быть как в своём, так и во внешнем проекте. Разделение не на уровне типа смены, а на уровне карточки проекта.

## Интерфейс

### Страница "Проекты"

**Параметры месяца.** Ползунок рабочих дней → сразу пересчитывается порог.

**Настройка коэффициентов** (свёрнута по умолчанию):
- Множитель порога — общий
- Множители грейдов S/M/L/XL — общие
- Коэффициенты смен — раздельно для ТВ и тех
- Коэффициенты внепроектной работы — раздельно для ТВ и тех
- Кнопка сброса к дефолту

**Свои проекты.** Для каждого — название, грейд ТВ, грейд тех. Ниже блок участия: все сотрудники обоих отделов, рядом с каждым таблетки смен. Клик по таблетке включает/выключает участие.

**Внешние проекты.** То же самое, но без грейдов — только участие.

**Экспорт/Импорт JSON.** Текущее состояние выгружается в файл или загружается из файла. Импорт полностью заменяет текущее состояние.

### Страница "Сводка"

Переключение ТВ / Тех → для выбранного отдела карточки сотрудников.

**В карточке сотрудника:**
- Итоговая сумма баллов против порога
- Полоска с разбивкой по источникам баллов (свои / внешние / внепроект)
- Статус: переработка / до порога
- Детализация по проектам — из каких смен собралась сумма
- Разворот "Внепроектная работа" в самом низу страницы — поля для ввода числа дней офиса, саунд-дизайна, сортировки по каждому сотруднику

## Чего в калькуляторе нет

**Намеренно упрощено:**
- Нет календарной сетки — работаем числами "сколько смен", без привязки к датам
- Нет механизма 3-месячного сглаживания порога (обсуждался в текстовом документе, в калькуляторе не реализован)
- Нет редактирования состава команды через UI — только через код или импорт JSON с изменённым составом
- Нет нескольких месяцев в памяти — один снимок за раз, переключение через импорт разных JSON
- Нет расчёта рублей — только баллы, перевод в деньги живёт в другом инструменте

## Хранение данных

**localStorage браузера.** Всё, что ты делаешь в интерфейсе, автоматически сохраняется. При следующем открытии файла в этом же браузере увидишь ту же картину.

**Что сохраняется:** проекты, участие сотрудников в сменах, количество дней внепроектной работы, коэффициенты, состав команд, рабочие дни месяца.

**Что НЕ сохраняется на сервере:** ничего. Это локальный файл, никуда не отправляющий данные.

**Потеряю данные, если:**
- нажму "Сбросить всё"
- очищу данные сайта/куки в браузере
- открою файл в другом браузере или на другом устройстве
- открою в режиме инкогнито (между сессиями не сохраняется)

**Чтобы перенести данные:** экспорт JSON → импорт JSON в другом месте.

## Типичные сценарии работы

**Моделирование одного месяца.** Заполнил проекты, расставил участие, посмотрел сводку. Покрутил коэффициенты — увидел, как меняется картина.

**Сравнение месяцев.** Сохранил январь в `january.json`, потом очистил и заполнил февраль → сохранил `february.json`. Открываешь нужный месяц импортом.

**Калибровка под реальность.** Прогнал 3–5 реальных месяцев, увидел, где цифры бьются с ощущением справедливости, подкрутил коэффициенты, экспортировал итоговые настройки как эталонный шаблон.

**Разные сценарии для одного месяца.** Сохраняешь базовый месяц → меняешь что-то (например, "а если бы XL-проект не случился") → сравниваешь. Возвращаешься импортом базового файла.
